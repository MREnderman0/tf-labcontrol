# JW8105 实机测试计划

## 目标与授权范围

先核对完整型号、固件、仪器序列号和 RS232/RJ45 选件。扫描只保存系统枚举，不打开未知串口。只有厂家确认的串口帧参数和只读身份命令归档后，才允许针对用户明确选择的单一资源执行身份核验。

## 前置条件与备份

运行前核对正式运行目录、库存、全局硬件锁和型号/资源锁的最终物理路径。协议资料允许先执行 `0x0140` 通信级身份、功率、波长、采样率、显示波长和 PDL 读取；停止位仍需厂家确认。保存光功率计各通道的波长、采样设置、校准/零点状态及 PDL 结果的只读快照；任何一项无法读取或无法恢复都阻止写入测试。USB 串口桥信息不得代替仪器身份。

## 停止与恢复

遇到超时、未知响应、解析错误或读回不一致，停止后续写入，不重发不确定命令；先读实际状态，再按已有备份恢复。恢复失败时写明最终状态未知，保留原始通信和恢复差异。未取得完整型号、停止位和序列号来源确认前，不把模型级身份或可逆参数测试提升为整机验收，也不形成物理输出结论。

## 可逆写入入口

使用 `python -m lab_control.instruments.devices.joinwit_jw8105.hardware.validate_control --resource <所选COM端口> --asset-name JW8105-UNKNOWN-<人工资产号> --confirm`。入口只接受一个明确的 COM 端口；先保存完整备份，然后对波长、每个采样率通道和显示波长各执行一次确认写入、读回、恢复写入和恢复读回。`--confirm` 缺失时不会打开设备。最终快照必须逐项等于备份，否则批次只记录失败或最终状态未知，不继续重试。

现场选定串口的实际批次已通过：波长 `1310.0 → 1311.0 → 1310.0 nm`，采样率通道 1–8 均 `4 → 5 → 4`，显示波长首项 `850 → 851 → 850 nm`；共 10 次确认写入，最终完整快照匹配备份。该批次没有覆盖通道 9–16，不能据此宣称 16 通道实机验收。重连沿用同一设备的前一只读批次，物理输出仍未测量。

## 交付与未测

每次枚举、失败、受阻和中止都新建运行批次。批次必须保存 `record.md`、`results.json`、派生 `summary.json` 以及原始扫描/通信/快照；真实地址、序列号和通信只放运行目录。未完成身份和物理测量前，结论只能是枚举证据，不是整机验收。
