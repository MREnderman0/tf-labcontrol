# 53220A LAN 硬件验证计划

## 目标与授权范围

接受一个明确资源和预期序列号，使用正式会话、进程锁和资产锁；不控制其他设备。先只读，再按显式 `--control` 执行参数测试。CH1 可接用户提供的约 100 MHz 信号；幅度未知时保持其原输入阻抗，输入切换测试只在悬空 CH2 执行。CH3 不启用。

```powershell
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.keysight_53220a.hardware.verify --resource '<VISA资源>' --expected-serial '<完整序列号>'
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.keysight_53220a.hardware.verify --resource '<VISA资源>' --expected-serial '<完整序列号>' --control --duration 60 --test-empty --input-condition 'CH1约100MHz，幅度未知；CH2悬空'
```

只读入口也通过型号 `readonly_check` 注册供正式 CLI 使用。每次运行创建新批次；不得重复使用已含 results.json 的目录。

## 前置条件与备份

确认正式库存、运行根目录和硬件锁为同一物理文件，保持其他进程修改。只读 `*IDN?` 和选件验证后保存当前功能、两路输入、触发、闸门、数学处理、格式、参考和输出状态。快照失败阻止写入。手动电平只在空载 CH2 关闭自动电平后验证，再恢复原自动模式与相对阈值；自动产生的瞬时绝对阈值不作为可重复设置。外部参考、设备地址和输出不作为本次修改项目。

## 停止与恢复

任一设置不确定即停止后续测试写入，不重发。异常通信仅允许持同一锁重新连接以读回、恢复；不重跑失败测试。逐项恢复本批修改的设置并比较。自动电平恢复其模式与相对电平，不声称瞬时绝对阈值恒定；此前在途测量不自动重启。恢复失败明确保留未知状态，不复位、不修改网络、不自动重启。

单独恢复使用 `--restore-from '<原批次/results.json>'`，先验证资源及预期序列号一致、保存当前状态，再恢复该批原始快照；本次恢复另建批次，不覆盖原失败记录。错误队列在控制预检时逐条读取留存，最多 32 条，不执行 `*CLS`；一次无效测量的 +321 错误与该回包一起读取，不重启测量。

## 交付与未测

成功、失败、中止、锁占用都保存原始 results.json、record.md、通信与快照，并生成 summary.json；通过公共 `refresh_after_batch` 更新资产状态和索引。约100MHz参考不是校准依据；物理精度、其他接口和整机验收分别列为待测。源码仅存脱敏协议样本。
