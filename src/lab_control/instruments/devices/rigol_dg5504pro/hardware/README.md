# DG5504 Pro LAN 控制验证

先核验完整型号/序列号，配置仅保存本台真实 VISA 资源。使用 `.venv-dev` 和已安装的 x64 VISA。实测前核对运行目录、库存及固定硬件锁的物理路径与正式程序一致，释放已有真实会话；不终止其他进程、不绕过文件系统重定向后的锁。

```powershell
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_dg5504pro.hardware.validate_lan --config '<运行目录内单设备配置>' --preflight-only
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_dg5504pro.hardware.validate_lan --config '<运行目录内单设备配置>'
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_dg5504pro.hardware.validate_lan --config '<运行目录内单设备配置>' --restore-from '<同一资产原始测试批次>'
```

预检仅查询并留档，包括记录读取到的错误队列，不发送设置。正式验证先记录四路输出并确认 OFF，完整备份基础/高级参数、负载/单位、模式、耦合及文件目录；备份不完整、未知初始模式或辅助输出活动时阻止测试参数写入。

四通道分别覆盖基础波形、频率/幅度/偏置/相位、脉冲/斜坡、扫频、AM/FM/PM、突发；每项保存请求、实际读回、其他通道比较及输出状态。任意波形使用唯一新文件，覆盖 256/1024 点的单包/跨包上传和目录验证。当前手册未提供已核实的原加载文件名及文件内容下载查询，因此加载测试和逐点读回标记受阻，不伪称通过。

所有修改经兼容适配器和原会话 worker 执行。测试传输层拒绝输出 ON、触发、复位、清错及不在测试范围内的设置命令。超时不重发；停止后续测试写入，先读取实际状态再恢复。恢复 helper 仅写回快照值，先核验输出 OFF，逐项检查读回与错误；失败停止后续恢复步骤，保存实际差异，不报告完整恢复。

`--restore-from` 用于已停止的测试：核对原批次型号、资源、序列号与完整四通道输出关闭快照，保存原结果哈希，再以新批次重新确认当前状态。恢复前逐项读回，相同值不再发送设置，只修改仍有差异的值；不重跑测试矩阵，不覆盖失败记录。恢复成功后继续 60 次稳定读取和 3 次重连。已删除的临时文件不再次删除，原始目录与最终目录仍比较。

恢复顺序为退出测试模式、清理本批文件、恢复关联参数/模式和通道联动；最终四路输出仍为 OFF。恢复通过后交替读写 10 轮的结果与 60 次稳定读取、3 次重连分别判定。实际执行中重复写读在恢复前完成，稳定读取和重连在恢复后完成。

记录位于运行目录 `hardware-tests/<型号>-<序列号>/<时间批次>/`，包含报告、JSON、通信日志、初始/最终快照、发送波形及哈希。失败与受阻同样保存并更新索引。真实网络、身份和数据不提交源码。

## 离线摘要与历史导入

`records.py` 仅解释本型号记录，不连接设备。测试入口在原始 results.json 保存后更新 summary.json；实机步骤和恢复顺序不因摘要改变。按[统一记录规范](../../../../../../docs/testing/records.md)离线导入并重建总览，旧批次与人工连接说明保持原样。
