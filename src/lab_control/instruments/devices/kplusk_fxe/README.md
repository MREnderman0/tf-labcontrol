# K+K FXE / FXE2

## 能力与协议

本型号包接入 K+K Messtechnik FXE/FXE2 计数器的官方 K+K Library 21.2.2 与 Python wrapper 2.1。兼容层使用官方 `Multi_GetReportStruct` 读取完整二进制回报：`RT_DOUBLE` 且报告头在 `0x2000..0x3FFF` 时按小端 `double` 解码为 Hz，最多保留 24 个通道，并跳过消息、时间戳和心跳回报。设备处于官方相位平均模式时，`RT_PHASE` 报文按小端整数周期数和小端小数周期解码，用相邻设备时间戳的增量计算只读 Hz，并在批次元数据中标记为 `derived_from_phase`。状态页仍保留原始报告字符串；兼容层只读，不提供参数写入、自动设置或命令重放。

设备监测页位于“实时监测 → 频率计数器”。用户可勾选要显示和记录的通道，页面提供逐帧实时数值、趋势曲线、当前帧导出和连续记录；读取节奏、历史和写盘由公共监测服务负责。没有完整有效的二进制频率回报时，当前帧不会显示或保存，并把本次采集标为超时/解析失败。

24 路是协议上限，不代表当前设备已安装或正在回报的通道。连接时只读等待首个完整测量报告，能力快照发布实际通道数；未识别时显示等待状态。选路只改变本软件显示和记录，不设置仪器通道；全部取消会保留空选择，失效选择明确提示，记录及收尾期间锁定选路。

状态、原始报告与频率采集共用单一报告读取器，最多保留 64 个待消费测量报告，缓冲满明确报错；只查固件或用户号不读测量队列。等待按单调时间计算，未知周期最多 30 秒，已知周期为 `max(10 秒, 2 × 报告周期 + 5 秒)`、最多 45 秒，消息数量不缩短等待。真实通信或解析错误仍立即失败。相位差先分别相减整数和小数，避免长时间累计的精度损失；重复/回退时间戳、报告模式或通道数变化重新建立基线，不猜测时间间隔。

## 连接与驱动

后续 K+K 统一按 DHCP 部署。FXE2 在对应的官方配置工具中启用 DHCP，设备取得实验网租约后以 `transport = "kplusk"` 连接，`resource` 为当次 IP（也接受 `kplusk://IP[:port]`）。项目通过官方库直接打开 `<IP>[:Port]`；`TCP:<IP>:<Port>` 是 K+K TCP server，不是设备直连。扫描只读，不修改设备网络、采集设置或电脑网卡。

身份识别只发送一次官方版本查询 `0x81`，等待 `0x7001 VERSION` 回包，解析实际 FXE/FXE2 型号、序列号和固件；缺失或不可靠身份明确失败。版本回包中的 IP 可能仍是旧配置，不能作为当前地址。查询与测量共用有界报告读取器，交错测量帧保留，不为扫描初始化采集。

| 项目 | 当前行为与边界 |
| --- | --- |
| 首次登记 | 明确设备型号和当前租约地址，只读核验完整型号与序列号后登记资产 |
| DHCP 跟随 | 以已验证地址关联有效租约 MAC，重新核验真实身份后保存绑定；后续按 MAC 查当前 IP，每轮再核对完整身份 |
| 地址变化 | 匹配成功后保留同一 UUID、槽位及用户设置；不固定当次租约 IP，不把旧地址写入静态地址清单 |
| 租约缺失或身份不符 | 不回退访问旧 DHCP 地址，不接管错误身份；未知租约不猜型号、不扫描端口 |
| 运行中变化 | 活动会话沿用已有句柄；停止并重连后使用新地址，不重放配置命令 |
| USB | 本项目运行配置默认 LAN；USB 可用官方工具确认身份和网络，须与 LAN 遵守同一资产占用锁 |
| 配置工具 | FXE2 必须用 FXE2 工具；现有 `kplusk-config-tool` / `launch-kplusk-config.ps1` 材料是旧 FXE1 工具，不得混用 |

官方材料版本、哈希和分发边界见 `deployment/packages/tools/kplusk/README.md`。本次发现修复复用已登记 K+K Library 与 wrapper，不安装新工具或升级固件。FXE2 配置工具尚未纳入部署清单；如后续准备该工具，须同时登记来源、版本、哈希、许可和下载页。

## 换电脑操作清单

- [ ] 停止采集和其他 K+K 软件，核对正式运行目录和硬件锁，备份库存、设备角色和实机批次。
- [ ] 新电脑准备已登记的官方 Library/wrapper，选择实际实验网口，复用已有 DHCP；独立交换机需要另行配置 DHCP 服务。不要复制旧网卡 GUID、租约、防火墙规则或绝对路径。
- [ ] 设备保持 DHCP。若需修改配置，先用对应型号的官方 USB 工具备份原值，只改授权的网络字段，写入后重启并读回；不同时更新 Firmware/Bootloader、CAN 或报告模式。
- [ ] 取得当前有效租约，以完整型号及序列号核验设备。首次或租约关联丢失时明确新地址后重新登记，不按 IP 或旧目录名合并身份。
- [ ] 在项目扫描中完成租约关联和真实身份核验，再只读连接、关闭及重连，分别保存结果。换 IP 的软件回归不代替实机换租验证。

旧 FXE1 静态网络流程仅适用于确实不支持 DHCP 的旧设备，不作为本现场 K+K 默认部署要求；发现旧型号时先确认其能力与部署方式。

## 测试与限制

型号专属离线测试在 `tests/`，显式实机只读入口在 `hardware/readonly.py`。测试覆盖二进制解码、延迟首帧、大量消息、状态不吞帧、相位精度与时间回退、实际通道、界面选择持久化及逐帧记录。实机入口使用正式会话、监测页、记录器和一次重连，不在超时后循环重试；默认连续监测记录 60 秒并保存原始报告、数据、截图和阶段结果。

`tests/fixtures/capabilities-before.json` 保留原迁移基线；`capabilities-current.json` 在实际版本回包与型号解析测试的依据上新增 FXE2 精确型号匹配，测量能力、范围与命令契约保持原值。DHCP 跨层测试见 `tests/integration/test_kplusk_dhcp.py`；现场证据保存在运行目录，不写入这些夹具。

输入悬空时仅验证通信、显示和记录，不以底噪读数判断精度或输入信号有效。10 MHz 参考时钟与各通道待测输入分别记录，不能用参考已接代替测量输入已接。完整型号、序列号、参数控制、恢复和物理验收仍按运行目录批次判定。真实地址、序列号和原始通信不写入源码。

实机测试前置条件和留档入口见 [hardware/README.md](hardware/README.md)。

替换设备时保留新序列号，通过当前 DHCP 租约重新核验并登记新资产，执行只读身份/重连批次；不能把旧 IP 或旧资产身份继承给新设备。
