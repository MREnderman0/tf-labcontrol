# WaveRunner 9404M 硬件测试入口

本入口适用于已明确选定的资产，遵循[实机留档规范](../../../../../../docs/testing/records.md)。实际地址、完整序列号和允许范围从正式运行目录的独立 TOML 配置读取。

## 目标与授权范围

LAN PyVISA/VXI-11，仪器 Remote 选择 LXI。默认只读；`--write --empty-inputs` 表示设备空闲、四通道未接线，允许可恢复的基础参数、触发状态、格式及功能性波形保存测试。不控制其他仪器，不开启外部信号源，不做物理精度校准或故障注入。

```powershell
.venv-dev/Scripts/python.exe -m lab_control.instruments.devices.lecroy_waverunner9404m.hardware.readonly --config '<运行配置>'
.venv-dev/Scripts/python.exe -m lab_control.instruments.devices.lecroy_waverunner9404m.hardware.validate_control --config '<运行配置>' --write --empty-inputs
```

已有控制与恢复通过的独立批次时，可追加 `--capture-only` 单独补测波形、单次保存和监测记录；仍先备份及三次重连，结束核实恢复。该批次参数控制标为未测，不覆盖此前控制证据。

`--continuity-only --write --empty-inputs` 为短时调参续采入口，与 `--capture-only` 互斥。先读取 CVAR 范围及当前内存模式/点数/采样率，再测试点数、长短时基和偏移；每次操作保存请求、读回与监测状态。固定采样率模式可能忽略 MSIZ 对采样长度的限制，此时超预算会终止该候选，不切换模式或截短数据。已确认的量化必须同时有 CVAR 请求/适配值证据。

## 前置条件与备份

必须验证库存、硬件锁的最终物理路径与正式程序一致；被 AppData 重定向则拒绝硬件访问。设备级进程锁允许不同明确资产并行测试；同一资产、未知别名扫描和旧版排他锁仍会阻止冲突访问，不终止其他进程。每次连接核对完整型号和序列号，初次连接跳过格式初始化；保存全部通道、全局采集及传输设置。缺失/不可解析备份阻止任何写入，警告回包不算读取成功。

## 测试矩阵

| 项目 | 操作与预期 | 核验/证据 |
| --- | --- | --- |
| 身份与连接 | 指定身份，经正式工厂/会话连接 | 完整 IDN、驱动版本、路径与锁 |
| 只读与重连 | 全量快照、三次释放/重开 | 参数与身份均不变 |
| 通道控制 | 逐个显示、档位、偏置、耦合、倍率、触发电平/边沿 | 写入、严格读回、其他通道隔离、逐项恢复 |
| 全局控制 | 时基、水平位置、存储长度、触发模式 | 合法保守值、读回并恢复 |
| 状态 | AUTO、STOP、SINGLE | 状态读回；无输入时不要求 SINGLE 完成 |
| 波形 | 开通四通道，AUTO 后 STOP，读取四通道 | 描述、点数、单位、坐标、缩放、原始二进制样本 |
| 保存 | 单帧导出；30 秒监测/记录，刷新 0.5 秒、保存 1 秒 | 有效帧、记录文件、CSV、参数锁和停止排空 |
| 恢复 | 恢复通道、时基、存储及传输设置，再恢复采集模式；水平位置在存储/重启可能适配后最后核对 | 原值/终值逐项对比及差异文件 |

数值采用相对 1e-6、绝对 1e-15 的序列化比较边界；这不是测量精度容差。枚举/复合设置精确比较。变化测试值避开边界；无法通过现有能力完整恢复原值时该项目受阻，不扩大允许范围。

## 停止与恢复

所有类别统一结构化维护：最终摘要生成后调用公共 `refresh_after_batch`，更新当前结论、接口矩阵、功能覆盖、已知问题及批次表；不逐次追加现行说明。原始批次和恢复证据保持不变。

第一次错误停止后续测试；不重发不确定写入，不恢复出厂。仅按已保存备份恢复已改变设置；通信失效时允许一次只读身份重连以确定是否能够恢复，重连失败则明确最终状态未知。恢复失败不能写成功。正常关闭不暗示停止采集，最终触发模式独立读回。

独立恢复批次可由 `verify(..., restore_from=原批次results.json)` 指定备份，必须先核对完整资产身份并保存当前状态。只做一次恢复尝试，失败不重放；旧批次失败状态保持不变。原存储长度在软件范围之外时，仅在实时硬件 CVAR 范围内恢复该精确备份值，不扩大界面可设范围。

## 交付与未测

每批保存 results.json、summary.json、communication.jsonl、初末快照、恢复差异、源文件哈希和 record.md；功能测试可保存本批次波形，性能基准使用下述独立入口。更新总索引和资产连接状态，再通过离线工具更新总览。旧只读预检中的接口警告由本包离线转换器降为 blocked，原始文件保留。

空输入数据验证通信与存储，不证明电压/时间精度、带宽或硬件全部正常。USB/VICP、分段、数学、高级分析及已知信号物理验证另列未测。

## 缓存与保存效率基准

```powershell
.venv-dev/Scripts/python.exe -m lab_control.instruments.devices.lecroy_waverunner9404m.hardware.benchmark --config '<运行配置>' --write --empty-inputs
.venv-dev/Scripts/python.exe -m lab_control.instruments.devices.lecroy_waverunner9404m.hardware.grouped_queries --config '<运行配置>'
```

必须从与正式程序一致的原生 Windows 环境启动；参数、身份与锁不通过时留档并停止。基准仅打开指定资产，不广播探测。保持原时基/存储，开启四通道，以 WORD 和 WFSU SP0/NP0/FP0/SN0 读取完整窗口，结束逐项恢复。完整路径与缓存路径在 STOP 下验证数据/坐标一致，单通道与四通道各预热后 20 帧、重复三轮并交换先后顺序。VISA 块大小独立比较并恢复原值。

随后 AUTO 下各运行 60 秒 fastest 监测和记录调度（保存间隔 1 秒）。记录仅保存元数据、哈希、时间，不产生 CSV、样本二进制或分段数据库；实际曲线保存使用独立 `validate_control --capture-only --duration 10` 批次。性能结果包括查询数、字节数、通信/解析/排队时间及中位数/P95/最大值；帧间隔使用高分辨率性能时钟。可辨认的采集标识重复率与读取次数分开报告。

成组查询入口只读，不修改 CHDR；用完整单条回复逐项对照分号分隔的完整复合消息。任何长度/顺序/值不符即关闭该会话，不追加读、不拆分回退。该候选失败不改变已经独立通过的缓存路径。进一步方案与描述字段对应见[通信说明](../communication-research.md)。

## 历史身份响应头修复

`repair_identity.plan(records, verified_identity)` 仅生成严格受限的离线修复方案：旧记录厂家恰好多出 `*IDN `，原始回复解析后的型号、序列号和固件与刚取得的完整身份一致，且连接设置、资源、名称和槽位没有矛盾。保留原规范资产 ID、用户配置和原始备份；不同序列号、多地址、配置或槽位冲突一律拒绝自动合并。

执行方须先通过正式设备锁做只读身份核验并释放会话；持有排他维护锁、备份库存后，以单个数据库事务应用方案，并检查记录未被其他进程修改。活动程序持锁时不修改库存、不终止进程。修复后通过正式库存连接入口核验，跳过采集初始化，记录零设置写入。重新用 `run.bat` 打开程序以加载统一解析代码及修复后的库存。
