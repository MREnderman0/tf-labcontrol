# M300 实机测试计划

## 范围与前置条件

仅访问显式 `rigol.m300` VISA 资源与完整预期序列号，核对正式运行目录和硬件锁，使用项目 PyVISA、全局进程锁与资源/身份租约。只读入口只查询身份、模块和状态；控制入口要求明确 MC3132 物理通道。热敏电阻已接在指定两线输入，标称值及换算假设须由用户指定；不测试校准、复位、数字输出或其他设备。

## 入口

```powershell
# 只读身份、模块和状态；不运行 READ?、不修改触发间隔
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_m300.hardware.readonly --resource '<VISA资源>' --expected-serial '<完整序列号>'
# 已授权的热敏电阻接入测试；默认恢复原设置
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_m300.hardware.verify --resource '<VISA资源>' --expected-serial '<完整序列号>' --channel 428 --nominal 10000 --duration 12
# 多通道不同标称值：必须使用已识别插槽的物理编号；下例为第 4 槽
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_m300.hardware.verify --resource '<VISA资源>' --expected-serial '<完整序列号>' --group 401:416=5000 --group 417:419=10000 --duration 12
```

`--home` 必须指向已核验的正式运行目录，不可换目录绕过占用。`--leave-configured` 只在用户要求配置设备时使用：先完成恢复和重连核验，再显式留下指定通道的 TEMP/THER、标称阻值、℃ 和扫描列表。结束时关闭软件采集和会话，不持续后台读取。旧 `validate_control` 入口转发到相同计划，不再无条件修改触发间隔。

`--group` 可重复，不能与 `--channel` 混用；重叠、跨槽范围、非 MC3132 输入及不支持的阻值在通信前拒绝。`--input-condition` 保存传感器名称、接线和曲线已知程度。5 kΩ/10 kΩ 只决定仪器内置换算档位，不自动确认 MF501 或其他厂家的具体曲线。

多通道计划先保存所有目标输入和其同槽未选输入、继电器、全局扫描及原有读数。原扫描列表只能包含本次输入，继电器必须全部打开，DMM/触发/附加字段满足单轮条件。逐路切换 RES 并检查原自动量程已开启，采集三次完整扫描；随后按组切换 TEMP/THER 和各自标称阻值，验证三次 ℃、一次 ℉ 及连续记录。每帧必须按序包含全部选定通道，缺路或任一路无效则整帧不显示、不保存。恢复逐路处理已尝试写入的输入，失败不阻断其他输入恢复；完整状态和未选输入逐项比较。保留配置阶段失败则尝试恢复原设置，并单独记录该次恢复结果。

## 备份与步骤

### 保存连接配置

仅在用户明确确认当前接线及后续自动恢复范围后使用。与一次性 `verify --leave-configured` 不同，本入口把输入方案保存到正式库存资产的控制状态，后续正式连接自动检查并补齐差异；同一型号但不同序列号不会继承。LAN 登记启用已验证地址跟随，不固定当次 IP；新地址仍须先通过公共发现的完整身份核验。

```powershell
# 示例：保存用户已确认的 19 路接线，验证正式连接初始化、连续记录、停止和零重写重连
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_m300.hardware.connection_setup --resource '<当前VISA资源>' --expected-serial '<完整序列号>' --group 401:416=5000 --group 417:419=10000 --duration 10
# 停用自动恢复，保留仪器当前设置及原有日志
.venv-dev\Scripts\python.exe -m lab_control.instruments.devices.rigol_m300.hardware.connection_setup --resource '<当前VISA资源>' --expected-serial '<完整序列号>' --disable
```

登记入口使用独占锁并先以 `configure_acquisition=False` 核对身份、备份全部已识别输入和原读数，再保存显式授权。正式重新连接测试才应用方案。仅温度模式、传感器类型、标称阻值、单位和扫描列表属于写入范围；不重置仪器，不修改网络、触发或未选输入。已有不兼容的活动状态或模块变化会阻止写入。登记前后的存储状态、设置快照、逐条写入及读回、监测分段、重连和失败均归入本批记录。

配置已正确时连接不重写；不确定写入会在持久日志中阻止后续自动重放。失败不自动补偿，记录最后核验状态；先核实原因和当前设备状态，再通过本入口重新授权。成功后保留用户方案并停止监测。未模拟真实断电或改 IP 时，不能把软件地址变化回归写成实机换址验收。

### 一次性热敏验证

1. 枚举仅收集资源广告；先在独占探测租约下核验精确身份，合并到原资产，保留旧地址/历史，再通过正式会话连接。记录 Python/PyVISA、VISA 路径、源码版本和型号源文件哈希。
2. 读取目标及同槽其余 31 路配置、继电器状态、DMM、触发、监视、扫描列表与所有读数字段。扫描列表须为空或仅含本次通道，全部继电器打开；DMM 已启用、IMM、次数 1、监视关闭、附加读数字段关闭。若条件不符，停止，不自动改成预期条件。
3. 保存 `DATA:POIN?` 和已有 `FETC?` 读数。后续 READ? 会覆盖内部内存，旧数据留在批次，不能宣称内存恢复。
4. 临时切换 RES（要求原电阻自动量程已开），设置单通道扫描并读取 3 帧；不更改潜在的电阻范围设置。首次自动量程变化使帧无效时，限 30 s 重新采集，记录丢弃原因；不重放参数写入，不重试超时/解析错误。
5. 切 TEMP 后备份原温度传感器和单位；切 THER 后备份其原标称阻值。设置本次标称值、℃，读取 3 帧；临时改为 ℉ 验证 1 帧，再恢复 ℃。核对其余 31 路配置未改变。
6. 使用公共监测和有界记录流水线运行指定 1～60 s。停止、等待二进制收尾和 CSV，逐项核对收到/提交/转换/实际文件帧数、真实通道及单位，并记录参数解锁状态。
7. 无论成功或异常，停止监测，先读当前值，再逐项恢复潜在热敏阻值、单位、传感器、扫描列表及原测量功能；恢复某项失败仍检查其他项目，不重放不确定的测试写入。比较全部快照和错误队列，关闭并重连核验。恢复失败明确报告最终状态未完全确认。
8. 仅全部必需测试及恢复通过后，执行显式 `--leave-configured` 配置，并再次读取一帧和最终快照。

## 记录与未测项目

每次测试，包括失败/受阻，都保存独立 `results.json`、`summary.json`、`record.md`、原始通信、初始/最终快照、逐帧文件及记录目录。调用公共 `refresh_after_batch` 更新台账；离线总览按公共导入/检查命令重建。真实地址和序列号不得进入源码。

温度只证明指定内置曲线的读数链路；未用参考温度计或标准电阻验收精度。未接的其他输入、USB、热电偶/RTD、AC/电流、外触发、多轮及混合单位采集均单独列为待测，不将通信或参数通过写成整机验收通过。
