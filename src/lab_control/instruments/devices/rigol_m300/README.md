# RIGOL M300

注册标识 `rigol.m300`。精确匹配厂家 RIGOL / RIGOL TECHNOLOGIES 和型号 M300；实际序列号、固件、插槽均由实机查询，不从地址推断。

## 能力与协议

依据 [M300 Programming Guide](https://www.rigol.com/dam/global/downloads/brochures/en/program-guide/data-aquisition/M300_ProgrammingGuide_EN.pdf) 的 FUNC/CONF、TEMP:TRAN、UNIT:TEMP、ROUT:SCAN、TRIG、FORM:READ 和 READ/FETCh 章节。当前输入控制覆盖 **MC3132 32 通道多路复用模块配合 MC3065 DMM**；其他插槽保留身份展示，不猜测输入能力。

| 能力 | 实现及边界 |
| --- | --- |
| 身份与状态 | 读取五个插槽、DMM 状态、扫描列表、触发、监视及错误队列 |
| 物理通道 | 由 MC3132 插槽动态生成；例如插槽 4 的第 28 路为 428；通道 1 为整机参数入口 |
| 输入设置 | 正式采集使用 VOLT（直流电压）或 RES（两线电阻）；温度从 RES 按绑定曲线计算；TEMP 参数仅供原状态查询及维护 |
| 扫描列表 | 显式设置 `(@428)` 或已识别输入的升序列表/同槽范围；`(@)` 清空；写入需确认 |
| 采集与记录 | 显式 `READ?` 单次扫描，按真实通道返回电压、电阻或软件换算温度，TEMP 直读在启动扫描前拒绝；接入公共监测及逐帧有界记录流水线 |
| 监测界面 | 趋势图配一块紧凑双列读数列表，每行按通道顺序从左到右显示两个通道；每组为圆形曲线勾选、通道号、读数、单位及温度峰峰值（最近 30 min）；保留监测、完整扫描记录、保存当前帧和适应曲线 |
| 一致性 | 前后核对扫描列表、每路配置、单位、触发及格式；完整回包发生配置变化时丢弃，自动量程暂态由公共调度限时处理 |
| 已授权连接配置 | 按完整身份保存逐通道曲线 ID 和温度单位；换地址或接口后继续匹配资产。新电脑须登记同样曲线，旧直读配置报错，不回退内置温度 |

`READ?` 会启动扫描并覆盖仪器内部读数，**不是被动查询**。扫描发现、只读连接、状态同步和参数查询不会调用它；页面点击“开始监测”直接发起已确认的扫描请求，不弹二次确认，兼容层 API 仍要求显式确认。连接不复位、不改数据格式、不启动测量。没有显式保存的连接配置时，不写输入设置或扫描列表。

页面显示正式连接核验后的输入设置和扫描列表，不提供输入参数编辑器。列表显示当前完整扫描通道，表头固定、空间不足时纵向滚动；奇数通道的最后一行只显示左侧一组。圆形勾选仅控制曲线显隐，取消后该通道读数仍更新，连续记录和保存当前帧均保留全部扫描通道。完整数值和更新时间可悬浮查看。空扫描列表禁止启动。未启用保存配置时，在仪器面板配置后重新连接；启用后，正式连接恢复已授权配置，接线改变时须先更新或停用保存配置。兼容层显式参数 API 保留供维护及硬件验证使用。

保存配置由 [连接配置维护入口](hardware/README.md#保存连接配置) 显式登记，保存在运行目录的资产状态中，不把地址或真实序列号写入源码。型号、序列号、固件及输入/DMM 模块身份必须一致；LAN 新地址经只读身份核验后由公共库存合并到同一资产。地址尚不可发现或身份有冲突时，不猜测设备。配置只在正式连接及已授权重连的 `prepare_acquisition()` 中应用，`configure_acquisition=False` 和扫描过程完全跳过。写入前保存原状态，逐项只写差异并读回，未选通道、继电器及全局参数保持核验。已有非授权扫描通道、监视开启、外触发或继电器闭合时拒绝修改。

曲线与系数随型号包分发，不依赖 Downloads。MF501 使用自然对数且 R 单位为 ohm；Excel 使用 R/10000 的自然对数，并按电阻下限选择四段系数。旧 schema 1 标称阻值配置已停用，必须显式改为 schema 2 曲线配置，不能自动按标称阻值推断。历史数据保持原样。

实时峰峰值由公共监测服务逐通道维护：不足 1800 s 使用本轮所有有效样本，之后仅保留最近 1800 s，包含边界；单样本为 0，无样本为“—”。隐藏页面或曲线不影响统计；停止冻结，再次监测重新计数。原始记录保留完整精度的温度及电阻元数据，CSV 温度列维持原结构。

配置日志在每条写入前持久化。超时、写入/读回失败或写入后的存储失败会阻止下次连接自动重放，并保留最后核验状态；须先检查实机，再显式重新授权。设置恢复不会自动开始监测，也不自动恢复仪器读数内存。

仅因扫描条件不符而在写入前受阻时，保留已核验的连接，设备池显示“采集待准备”及触发次数、附加字段、继电器等具体原因；不会标成连接故障。开始监测只显示暂停提示，不发送 `READ?`、不保存无效帧、不自动重连或停止外部扫描。调整仪器后须显式重新连接以重做预检。另行授权的维护切换必须先备份设置，停止并核实扫描状态，再备份读数内存、修改单轮触发与格式并逐项读回；不能将一次维护授权变成后续自动连接的停止命令。

离线处理声明为标量时间曲线，各扫描通道按实际温度、电压、电阻等物理量及单位分组，完整保留原始采集记录；温度增加记录末尾 30 min 峰峰值和汇总 PNG。处理不读取或修改仪器扫描配置；使用方法见[数据处理](../../../../../docs/guides/data-processing.md)。

## 连接与驱动

优先 LAN VXI-11 或 USB VISA，复用已登记的 `rs-visa`（Windows x64 VISA Runtime），不附带厂商 DLL。组件来源、版本、检测与安装边界见 [组件清单](../../../../../deployment/components.json) 和 [下载资源](../../../../../docs/generated/download-resources.md)。不新增 Python 包、驱动、端口服务或网络配置；枚举不修改网卡/DHCP/防火墙。USB 接口仍需独立实机验证。

## 单位与限制

| 参数/采集 | 范围或条件 |
| --- | --- |
| 触发间隔 | 0～359999.999 s |
| 热敏曲线 | `mf501-v1`：MF501 文档公式，−30～60 ℃；`4813-s02-v1`：用户 Excel 四段系数，−50 ℃ < T < 150.001 ℃ |
| 温度单位 | C、F、K，导出为 °C、°F、K |
| 温度设置 | 正式连接只将已授权通道设为 RES 并恢复扫描列表；保留原电阻量程；C/F/K 单位由软件转换 |
| 当前扫描采集 | DMM 开启、监视关闭、触发 IMM 且次数为 1；UNIT/TIME/CHAN/ALAR 附加字段关闭 |
| 多通道显示 | 同次扫描须使用相同测量功能和单位；请求通道须匹配扫描列表，旧 `(1,)` 请求表示当前扫描列表 |
| 混合传感器 | 每路显式绑定曲线，不根据标称阻值或通道号猜测。原始帧保存实测 ohm、曲线 ID/版本、来源哈希与 RES 配置 |
| 无效读数 | 数量不符、截断、NaN/Inf、开路或溢出哨兵（绝对值 ≥ 9e36）拒绝显示/保存；通信/解析错误不自动重试 |

传感器只有“10 kΩ”标称值不能证明其曲线与指定传感器一致。显示温度属于所选曲线的换算结果，独立精度验收需传感器资料及参考温度计。已核实的数据路径为 ASCII；未确认厂商支持可用于此采集的二进制返回格式，不猜测二进制协议。

## 文件与公共依赖

`profile.py` 定义命令/范围，`protocol.py` 解析完整响应，`adapter.py` 管理动态通道和配置一致性，`connection_setup.py` 管理按身份授权的连接配置及写入日志，`thermistor_curves.py` 保存已核验公式、系数和文档来源哈希；[tests](tests/test_acquisition.py) 为脱敏、人工构造的协议回归，格式已在实机试读核对，不冒充完整硬件录制。硬件入口、恢复及离线转换位于 [hardware](hardware/README.md)。公共层只提供会话、租约、监测、存储和通用扫描通道展示。

## 已知限制与待测

| 功能或问题 | 限制 / 原因 | 后续验证 |
| --- | --- | --- |
| 温度准确度 | 已采用用户提供的两类传感器公式；尚未以独立标准验收准确度 | 外部参考温度计或标准电阻 |
| 其他模块、热电偶/RTD、AC/电流 | 当前未实现对应输入采集与保护条件 | 独立模块协议和实机计划 |
| 外触发、多轮扫描、附加读数字段 | 当前只支持有界即时单轮纯数值回复 | 增加帧协议、停止与恢复验证 |
| 仪器读数内存 | 新扫描会覆盖；可备份原始读数但不能恢复内存 | 测试计划明确备份，软件记录独立保存 |
| 未接输入与其他接口 | 已测通道不能替代未接输入或 USB 验收 | 分批补测，保留历史失败 |
