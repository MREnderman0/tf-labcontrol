# 实验网发现与地址变化

公共发现层负责 LAN 枚举、身份核验、地址归属和历史库存；型号模块只负责该型号协议、范围及控制。不会把 DG5504 Pro、SMA100B 等型号分支加入网络层。

## 启用方式

Windows 新部署缺少配置时，自动发现当前已连接的物理以太网网口；每轮重新获取 IPv4 网段，不缓存旧网卡 GUID 或地址。Wi-Fi、VPN、虚拟网卡和断开的网口不加入自动作用域。拔掉全部网线时返回空结果，重新接入或换 USB 网卡后下一次扫描使用新网段。

可在正式运行目录 `config/lan-discovery.toml` 中配置，不把现场网卡 GUID/IP 写入源码：

```toml
enabled = true
auto_ethernet = true
timeout = 3.0
# 如需进一步约束，可填写 networks = ["192.0.2.0/24"]（此处为文档示例网段）。
```

已有显式配置继续生效。固定实验口可省略 `auto_ethernet`、填写 `interfaces = ["<实验有线网卡的 InterfaceGuid>"]`；自动模式不与固定 GUID 混用。`enabled = false` 明确禁用；非 Windows 平台仍须配置网段。自动发现不会安装 DHCP 服务、修改防火墙或仪器网络参数。GUI 启动和原有“扫描”入口使用同一发现服务，CLI 扫描同样生效；不增加后台周期控制或自动写入。

当前复用 R&S VISA 的资源管理器扩展：`VI_RS_ATTR_TCPIP_FIND_RSRC_TMO` 和 `VI_RS_ATTR_TCPIP_FIND_RSRC_MODE`，模式 6 为 VXI-11 + mDNS，不把静态 VISA 缓存当作发现证据。运行库会枚举所有网卡，公共 provider 仅允许实验网卡/网段里的 INSTR 候选进入身份探测；不逐 IP 或逐端口扫描。查询前后的资源管理器属性在同一运行库锁内保存和恢复。其他 VISA 后端不支持扩展时报告该 provider 受阻，USB/配置资源仍可使用。

参考：[LXI 网络协议](https://lxistandard.org/lxi-protocols/)、[R&S VISA 官方说明](https://www.rohde-schwarz.com.cn/driver-pages/remote-control/3-visa-and-tools_231388.html)。

## 身份与资源

- 厂家、完整型号和可靠序列号形成身份键；持久库存 UUID、名称、槽位、草稿、历史记录不随 IP 改变。
- 重新核验到同一身份的新 LAN 地址后，默认只更新连接地址/传输类型并绑定序列号，保留原有超时、实验限值、选件及其他配置。
- 再次发现已核验且未撤销的 LAN 地址时，身份探测沿用资产保存的连接超时，避免退回广播发现的短超时；显式配置仍优先。这里只复用超时，不把旧型号、序列号或限值传给未知身份的探测连接；扫描日志记录实际探测超时，失败不自动重试。
- 明确手选的主资源保持固定，新地址作为候选显示。USB 主资源不因发现 LAN 自动切换。
- 公共运行时 `select_resource(..., follow_address=True)` 可将已核验的 LAN 资源设为默认并允许跟随地址变化；要求可靠序列号、候选地址的身份归属一致且没有冲突。后续扫描只在重新读到相同身份后更新 LAN 地址，保留 USB 候选及原限值、超时、选件和资产记录。原有界面手选地址仍采用固定模式；此参数不会修改仪器网络设置，也不会启用 DHCP 或后台自动重连。扫描或活动连接期间拒绝修改主资源。
- 一个旧 IP 出现新身份时，旧资产的该地址标为已撤销归属；新资产不会继承旧资产的限值和序列号。旧资产和通信历史保留。
- 缺少可靠序列号的自动发现 LAN 设备禁止控制；不同设备不按 IP 或型号合并。相同身份在一次扫描中被两个不同 LAN 主机同时确认时保守标记冲突，需要人工核对。相同主机的不同协议、已确认的 USB/LAN 身份可归到同一资产。
- 不同时间的 `connected`／`manual` 记录使用重复的会话标签，不能作为“同一轮发现”的证据；更换地址后连接不与旧连接历史判为同时在线。旧版本仅由这类标签生成的多地址冲突，必须在重新读到匹配的真实身份后才解除；真实扫描批次的冲突及其他身份冲突继续保留，活动会话仍由身份租约防止重复连接。
- 历史资源保留用于追溯，但仅本轮核验仍存在的归属参与活动别名租约，防止旧 DHCP 地址永久占用其他设备。

活动会话只使用原有身份缓存。无法排除新资源为活动设备别名时，显示候选并延后身份探测；扫描不打开第二控制句柄。失联后停止后续写入，更新候选地址并由用户重连，重新校验型号和序列号。不自动重放失败写入，不用扫描结果伪造设备在线状态。

扫描运行期间（包括枚举、探测及收尾）暂不接受新连接；设备池禁用连接/重连并提示等待，公共运行时也原子校验这一限制。本轮确实收到 LAN 广播或本地枚举、随后身份探测失败的设备保留在“当前设备”中并明确显示错误，供用户查看原因；仅有旧配置的失联地址不会因此成为当前设备。连接中的设备保留可见，但不进入已连接设备选择器。异常概要显示在设备详情顶部，完整错误仍保留在原有详情中。

发现记录区分探测错误与驱动故障，保留 `probeErrorCode` 和审计 `errorCode`。只有明确的运行库缺失错误标记驱动不可用；连接失败、超时和旧的未分类失败显示待核对，不能据此宣称驱动损坏。

## 组网建议与边界

多设备 DHCP 应使用通用地址池，不用单设备 MAC 保留名单代替。配置准备和换电脑检查通过 `lab-control-cli network inspect/plan/validate` 完成；具体步骤与当前自动化边界见[实验网络部署与换电脑](../guides/lab-network-deployment.md)。方案按本机网卡和网段生成，普通发现不应用方案或启动服务。

普通交换机通常不提供 DHCP。带 DHCP 的实验网可让电脑和仪器自动获取地址；独立交换机应统一静态网段，或在设备支持时采用 AutoIP。当前电脑双网段属于现场部署配置，不写死进发现代码。未来 DHCP 改变网段时，按网卡 GUID 选取的发现范围随当前地址变化。

电脑直连时，仪器的 DHCP 客户端需要实际 DHCP 服务器才能获得租约。由电脑提供该服务属于独立部署操作：先核对实验网口、已有服务器和地址范围，再配置网口限制及 Windows 授权。扫描发现与地址分配分别验收，不能把固定地址连接成功写成 DHCP 通过。换电脑重新检测运行库和网络；不能复制另一台电脑的 GUID、防火墙程序路径或租约配置后宣称可用。

频繁拔插与换口的目标包括保持资产 UUID、名称、槽位、草稿及历史，重新发现后以完整身份核验新地址。换交换机端口与换电脑网卡分别测试；后者不得依赖旧 GUID。自动扫描当前网口不等于已实现 DHCP 服务迁移或后台自动重连。失联期间不继续参数写入，重连不重放此前失败的命令。

广播/多播可能被 VLAN、路由或防火墙隔离；发现失败不代表设备不支持 LAN。仍可通过明确资源配置接入；软件不承诺发现任意不可达网段。

## 验证

`tests/integration/test_lan_discovery.py` 覆盖作用域过滤、20 台设备地址变化、旧地址复用、固定主资源及身份冲突；现有会话与库存测试覆盖扫描取消、占用锁和活动会话保护。Mock 的 IP 变化测试不冒充真实交换机/DHCP 验证；现场结果按资产单独留档。

自动作用域的 Mock 验证覆盖首次部署、显式禁用、配置兼容、拔线空结果、换网卡/网段后重新枚举和显式网络限制。扫描不把无 IPv4 的网口误报为驱动缺失。
