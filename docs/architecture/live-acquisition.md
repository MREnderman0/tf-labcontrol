# 监测一致性与调度规则

这些规则适用于现有及新增型号。通用会话、帧调度和保存策略放在公共层；配置快照、命令、数据格式及允许变化的判断留在独立型号包。不能用针对某个型号的公共分支修补监测行为。

## 完成设置与取得有效曲线是两个阶段

命令被接受、`*OPC?` 完成或参数写入成功，不代表随后多次查询得到的是同一瞬间的配置。自动设置、自动量程和前面板操作都可能影响后续读取。先完成当前读取，再串行执行设置；组内读回结束前暂停后续自动采集。禁止重发已执行或执行结果不确定的设置命令。

首次和显式完整采集核对采集前后快照；已声明缓存依赖及失效路径的型号可在后续监测/记录中只读曲线，遵循下述快照契约。只有完整回包已经通过长度、点数、有限数值及格式检查，且确实发现前后配置差异时，型号适配器才可抛出 `DeviceError(code="configuration_changed")`。错误详情列出变化字段及前后值，不只报告笼统的“配置变化”。截断、乱码、无效点数、NaN、超时和断线不能归入该类。

公共会话保留可用连接并递增配置版本；旧配置读回不再作为当前数据。公共监测丢弃该帧，不绘制、不导出、不补零；按正常轮询间隔读取下一帧。Auto 或前面板调整造成的变化从首个无效帧起最多等待 30 秒，后续丢帧不延长期限，不按三帧判为故障。等待时只显示中性提示，取得有效帧后恢复正常监测并清除等待期限。30 秒内仍不稳定则以提示状态暂停读取，连接不降级、不显示设备故障；已在途的查询按原超时收尾，迟到帧不显示、不保存。单次读取及兼容的新读帧导出接口仍只尝试一次；保存已显示帧不发起读取。该处理不增加设置写入、恢复输出或重发命令。

直接 `start_acquisition` 遇到 `configuration_changed` 时同样保留连接并递增配置版本，但本次直接采集以原错误结束并排空已接收数据，不沿用监测轮询的自动等待策略，也不自动重试。

连续监测与连续记录遇到读超时、断线、损坏回包或采集数据缺口时，丢弃失败帧，进入自动重连并保留原任务、记录批次、已提交文件及资源租约。首次立即尝试，失败后按 0.2、0.5、1、2、5 秒退避，此后每 5 秒继续尝试，不因离线次数耗尽而永久停止。每台设备只有一个读取或重连在途，不排队补采丢失的帧；其他设备继续运行。设备池显示“自动重连中”，恢复期间停止按钮仍可使用，用户停止或退出取消后续尝试，并等待当前有界 I/O 和二进制保存收尾。

连续采集默认把普通读等待放宽到至少 10 秒，原连接或型号声明的更长预算保留。慢帧只要完整有效仍接纳，保存主机实际读开始、读完成和耗时；仪器原时间轴保持不变，不拿目标间隔推算时间戳。预算通过 worker 局部上下文传递，VISA/串口/TCP 在整帧请求发出前临时设置，整帧结束后恢复原值，接收期间不改串口参数；独立连接、用户控制和其他设备的等待不被修改。SDK/专属流只调整已声明的采集截止，不猜测驱动 API。永久不应答仍需要有界等待后重连，不能无限占住 worker。

公共恢复在原 worker 上重建原地址的适配器，核对原厂家、型号及已知序列号/固件，使旧配置缓存失效；取得首个有效帧才结束缺口，并在该帧配置加入 `_acquisition_gap`。记录目录 `_raw/acquisition-events.jsonl` 保留中断、恢复和未恢复即停止事件，即使中断后没有新帧也保留证据。坏帧不显示、不保存，不补零、不插值。记录缓冲满或写盘失败仍明确暂停；不把保存失败当成通信问题掩盖。

单次读取、手动控制、身份冲突、配置/初始化结果不确定不自动重放。重连只允许原连接已经授权的型号格式初始化；初始化失败可能涉及不确定写入，须停止并明确报告。短暂通信中断可自动恢复，不意味着物理链路永不掉线或仪器设置在断电后自动还原。协议不能读回序列号的设备仍标为型号级身份，不能声称完成了序列号核验。

型号可通过只检查现有快照的 `acquisition_setup_needed()` 和返回完整 `ControlUpdate` 的 `prepare_acquisition_state()` 声明已授权的采集模式准备。发现模式不符且尚未发送波形请求时使用独立 `acquisition_setup_required`，不能冒充配置暂态或吞掉解析错误。正式会话仅在启用连接初始化、未记录且未收尾时，预留控制事务并递增配置版本，执行一次准备、合并已核验读回，再重新读取一次波形；其他失败不进入此路径。主动刷新共用同一准备接口，扫描和 `configure_acquisition=False` 完全跳过。型号留存前后快照和尝试过的命令，失败不自动补偿或重放。DHO924 的 MAIN 策略据此退出 ROLL，并保持稳定帧零额外参数查询。

示波器 Auto 明确拒绝且会话通信仍正常时，保留失败提示，使采集上下文失效，只读核对实际参数和范围；核对通过后才续原监测，不重复 Auto，也不在拒绝后的核对中自动调整点数。用户主动停止优先于任何自动续监测意图。Auto 成功后同样使用新通道集合续监测；原本未监测、全部通道关闭或会话变化时不自行启动。

监测页对已经停止任务的异常会话提供显式“重连”：公共会话在原 worker 上预留一次恢复，复用身份核验和格式初始化策略并保留资源租约；拒绝在途操作、活动监测、参数组及二进制记录收尾期间的重连。成功后更新会话标识、使旧缓存失效并回到可开始监测状态；失败保留降级和错误，不启动后台重试。手动恢复不续旧任务、不恢复输出、不重放控制。共享按钮只呈现该状态；活动自动重连仍由原监测任务负责，停止操作保持可用。

## 统一采集节奏与并行保存

型号可声明 `recorded_run_kinds`、纯校验 `validate_recorded_run()` 和 `run_acquisition(request, stop)` 有界生成器。公共会话仍负责进程/设备锁、单工作线程、容量预留、逐帧保存、事件及 CSV 收尾；型号生成器负责一次初始化、连续读取、有限时长和硬件停止，不在公共层分支识别型号。此路径禁止另设 count 或抽帧保存间隔。自然结束先撤销未用容量预留，异常或缓冲满关闭生成器执行停止；停止失败仍排空二进制并释放会话任务。CSV 完成回调不得延长参数锁或覆盖后续批次的界面状态。

有限硬件流需要型号提供 `recorded_run_state` 与 `resume_acquisition(request, stop, state, elapsed)`，保存剩余有效样本预算及当前配置。公共层不能重新调用旧的 start 来冒充续接。可选 `reopen_acquisition()` 保留型号拥有的服务，仅重开通信；可选 `cancel_acquisition_recovery()` 在身份核验完成后执行一次停止核验。无法核验连接时必须报告物理测量停止未确认。不同连续片段分开计算连续性敏感的统计量，禁止把断线两侧样本直接拼接计算稳定度。

- 采集节奏分为最快采集与自定义间隔。所有类别均按通用工作区和设备持久化间隔及节奏，重启、切页、重连和 Auto 后恢复上次选择。没有有效偏好时，频谱仪和示波器默认自定义间隔 0.5 秒/帧，光谱仪默认自定义 10 秒，电源默认 1 秒；其他类别沿用最快默认。电源公共间隔组件只提供 1、5、10、60 秒档位，不提供最快或自由输入，恢复时也校验档位。非电源页面的最快模式仍可手动选择，完整收完并校验一帧后立即安排下一帧。自定义范围 0.5～60 秒，定义为相邻请求的目标开始间隔。旧 API 未传 cadence 时保留原数值间隔语义。每台设备最多一个读取在途，慢设备不补发积压请求，也不降低仪器扫描时间。
- 自定义间隔正常按请求开始到开始计时；一帧超过目标间隔时，完整接纳后从收完时刻重新等待一个间隔，不连续补发错过周期。最快模式仍在有效帧完成后继续。慢帧不会降低数据质量，也不会被强制压缩到目标周期。
- 界面统一传入 `record_interval=None`，开始记录后每个有效采集帧都保存，不再使用第二个选帧计时器；开始之前已在途的监测帧不补存。旧 API 显式数值仍支持 0.05～86400 秒的独立选帧语义。旧界面偏好保留采集间隔，忽略保存间隔。
- 连续记录使用独立二进制写入线程，缓冲包含在途容量预留，最多 64 帧或 128 MiB。满时暂停接纳新的记录帧，排空已接收帧，显示原因并等待用户重新开始；纯监测可继续。写盘失败保留已提交文件和未提交数量，不自动重试、不静默跳帧。
- 总览一次启动至少两台有效勾选设备时，共用不可变批次根目录、时间和标识，通过 `MonitoringService.start(batch=...)` 传入各设备记录上下文；批次参数仅在开启记录时有效。设备目录准备、缓冲、写盘与失败处理仍各自独立，不增加统一等待或同步触发。停止后再次启动使用新批次；单台保存与设备页独立启动维持原目录规则。
- 停止及退出时，最后一项读取/写盘即使失败，也须在同一轮收尾释放监测占用和完成等待者；不能依赖已经准备退出的调度线程再运行一轮。
- 公共监测快照的 `stopping` 与启动门禁使用同一判定：任务已停止调度，但仍有在途读取、写盘、目录准备、重连清理或二进制排空。此时禁用单设备开始及单次采集；总览有勾选设备处于该状态时禁用一键开始，并在点击入口整体检查，不能先启动已收尾设备再遗漏慢设备。二进制及在途工作完成后恢复按钮，CSV 转换不延长等待；活动监测的停止和参数变更后的取消续监测仍可使用。
- 页面修改间隔只更新本地调度与偏好，不启动采集、记录或修改仪器扫描时间。总览和设备页统一读取设备级偏好；旧总览卡片间隔只在缺少设备级设置时迁移一次，不能覆盖已有设置。切换设备不能混用另一设备的设置。相噪定时采集的采样率和时长单独按通用工作区及设备保存，恢复时校验当前能力和范围；仅恢复界面选项，不发送设置或自动开始采集。
- 总览和设备页的间隔输入在失焦或回车时才校验并应用；中间文本（如输入 0.5 时的 0）与越界草稿允许保留，刷新及其他设备的同步不得覆盖正在编辑的文本。完成编辑后越界值收敛到边界，非法或空白文本恢复上次有效值。无设备增减时不重建总览网格，避免 Qt 重排重置输入内容。
- 总览明确修改某台设备的采样间隔时，同时将该设备的节奏设为自定义间隔，立即同步设备页的模式及输入状态，并一并持久化；运行中的任务同步使用该节奏。仅切换参与采样、刷新卡片或修改其他设备不能改变该设备的最快／自定义选择。旧总览独立间隔迁移时采用自定义节奏，已有设备级明确选择优先。
- 显示实际有效帧间隔，让用户区分目标频率与实际速度。诊断时分别测量设备读取、等待调度和写盘；不能只减小界面计时器后声称已达到指定刷新率。

读取完成主动唤醒调度器，按最近期限等待；后台设置同步也使用完成通知和全局错峰期限，不由固定短轮询驱动。最快采集仍让用户控制先进入会话队列，停止、手动保存和退出不能被饿死。Qt 新帧通知合并，实时路径只取最新帧；标量工作区同时保留有界回放窗口，隐藏页面不绘图，回切时补齐窗口内的历史。曲线通知不触发设备列表或参数编辑器刷新。发布时复制仪器复用的数组并设为不可写，嵌套元数据冻结，显示和存储可安全并行。

连续记录与直接 start_acquisition 共享公共发布契约和记录器。分段 SQLite/BLOB 格式为版本 1，每 60 秒或 64 MiB 轮转，数组保留 dtype/形状/字节序；配置及原设置时间按内容版本存储。独立子进程在界面路径固定每 5 秒转换已提交数据为 CSV（底层显式参数保留 1～3600 秒兼容），全局最多两个转换进程，每次运行只有一个转换在途。界面记录逐帧保存，CSV 周期只控制转换时间。停止记录排空二进制并补齐 CSV；仪器锁在二进制收尾后释放，不等待 CSV。CSV 失败单独报告，不回滚二进制；文件偏移与提交序号检查点支持恢复转换，未提交尾部会先截断。单帧手动导出和历史 JSON/CSV/NPZ 格式保留。

公共入口继续是 `application/sessions.py`、`application/monitoring.py` 和 `storage/recording.py`，旧调用签名及补丁入口保留。内部职责集中在以下模块，不改变原线程或锁的归属：

| 职责 | 维护模块 |
| --- | --- |
| 不可变帧、有效性与容量计算 | `domain/frames.py`；原 `application/acquisition_pipeline.py` 保留兼容导出 |
| 单次操作、采集与配置读回 | `application/session_operations.py`，使用原设备 worker |
| 直接连续采集与二进制收尾 | `application/recorded_acquisition.py` |
| 连续采集身份核验、退避及缺口；监测恢复调度 | `application/acquisition_recovery.py`、`application/monitor_recovery.py` |
| 完成通知、调度 tick 与期限 | `application/monitor_scheduler.py`，复用原监测线程和锁 |
| 显示帧、新读帧及存储帧导出 | `application/frame_exports.py`；状态类型位于 `monitoring_state.py` |
| 二进制消费、CSV 子进程监督 | `storage/recording_workers.py` |
| 记录完成证据及在途集合 | `domain/recording.py`、`application/recordings.py` |

共享控件仍为 `ui/pages/monitoring/timing.py`。单设备多个页面共享会话和采集，不创建第二连接；单次导出仍是独立用户动作。记录集合仅保留在途任务和最后一批，完成后清理旧对象；成功路径兼容已有路径列表，失败通过携带 `RecordingOutcome` 的记录错误保留已提交文件、计数及二进制/CSV 错误，不把写盘失败返回为成功。

二进制或 CSV 失败统一使用 `recording_failed`，缓冲拒绝使用 `recording_paused`；异常的 `outcome` 保存最终结果。已接纳的连接、普通设备操作、后台读取、采集、保存和记录完成 Future 不允许通过 `cancel()` 撤销已排队或执行的工作；仍须完成结果通知、计数及租约收尾。停止采集使用既有 stop 接口并等待收尾。构造失败和关闭按资源逐项清理，附加清理错误保留为异常 notes，不遮盖首个错误。

恢复和清理路径的诊断经 `storage/audit.py` 有界保留失败证据，可从 `runtime.diagnostics()["audit_errors"]` 查看；不因审计写盘失败跳过后续资源释放。要求在设备操作前持久化的严格审计仍保持失败语义。诊断失败不触发设备写入重试，也不覆盖原始设备错误。

型号可提供只读的 `capability_revision`，当完整报告确认通道或报告模式变化时递增。会话在任务收尾比较能力版本，仅从型号缓存发布变化后的能力快照，不额外访问设备；未知通道的空快照不得在界面回退为型号最大通道数。协议判定及缓冲留在型号包。

## 光功率滑窗与读数

公共监测任务为 `scalar/power` 维护按通道隔离的 1800 秒内存窗口，使用帧的主机单调接收时间；在完成质量、完整性及请求版本校验后更新，不依赖界面刷新或是否正在记录。曲线和峰峰值从同一个只读快照取得数据，最近 30 分钟包含全部有效点，不使用固定 1200 帧上限。时间队列负责淘汰，单调极值队列增量维护最大/最小值；原始测量及记录格式不受显示换算影响。

窗口由监测任务上下文隔离。通道集合变化只为受影响通道标记分段，保留窗口内历史；自动重连成功的首帧及配置暂态后的有效帧同样断开曲线，不插值或补零。页面隐藏、通道暂停和自动重连期间继续按时间淘汰；停止并排空在途读取后冻结最终窗口，再次开始创建新任务及时间原点。W 峰峰值为最大值减最小值，dB 峰峰值为最大/最小功率比的十倍常用对数；零功率不转换为无穷或伪造有限 dBm。光功率显示切换同时作用于读数和趋势，保留用户横向视窗。其他标量工作区沿用自身的回放与显示策略。

## 电源标量工作区

电源页面每周期仅提交一个包含全部勾选通道的 scalar 请求（points=1），同一不可变帧供电压图、电流图、实测数字和记录使用；总览电压／电流卡片合并为同一设备的标量请求。通道选择与输出设置分离，改变集合先停止并排空旧请求，再续原监测，用户停止优先；全取消停止，记录及收尾锁定选择。

设定值与实测值分离。监测期间无额外参数轮询，缺少有效设定缓存时在启动前显式读回；应用后在同一控制组中完成设置核对，再释放组并续采。沿用缓存不更新时间；有效同会话、同配置版本的输出缓存不会仅因同步暂停而不可操作。错误、未知输出、过期配置和记录锁仍保留原阻断规则。

电源间隔通过曲线工具展开，默认收起，实际帧间隔常驻底部。趋势以首个有效帧的单调时刻为原点，X 从左侧 0 秒向右增长；初始视窗 0～600 秒，超过后滚动最近 600 秒但不重置原点，用户手动视窗保持不动。暂停、调参不重置原点，时间差不按目标间隔合成；电压／电流单位分离，共享横向视窗。首帧留余量，后续只按新数据越界扩展 Y 轴，手动适配仅使用可见历史；不按软件间隔制造采样点。隐藏页面不绘图，参数改变保留历史，换设备／会话清空。显示帧保存固定所选通道的两种原始测量，遵循下述公共导出契约。

## 通信性能优化的共同要求

帧时间记录实际读取，不用目标间隔或帧序号推算时间。公共会话在读取前后采集 UTC 和单调时钟，`timestamp` 为读取及校验完成时刻；可选 `timing` 版本 1 保存开始、完成和实际耗时。记录器根据本次开始和帧完成的单调时钟保存相对时间，不使用排队或写盘时刻。各型号在波形回复收齐时记录通道接收时间，原生触发时间单独标明来源和时区；无法提供则保持未知。仪器时间轴不受软件刷新间隔影响。字段与旧格式兼容规则见[数据模型](../data/data-model.md)。

独立参数轮询统一低于监测和采数的优先级：所有型号空闲时当前设备每 30 秒、其他设备每 60 秒检查；每次最多四个轻量参数，全局相邻自动批次至少相隔 50 ms，并保留最多四个在途任务和设备间轮转。首次同步、周期到期以及长任务结束后的恢复都经过同一错峰入口，只从当前时间安排下一次，不补发错过的时间槽。间隔限制只约束后台任务，不节流用户应用、主动读取或采集。

会话在监测或记录期间拒绝独立的静默参数读取，连帧间空隙也不插入；停止后恢复低频同步。DSA815 按用户确认的稳定配置策略取消帧间及周期参数查询：启动时完整核对，后续只读轨迹；软件设置、Auto、主动刷新、异常、重连和新运行批次使快照失效。型号维护坐标、单位、格式依赖；缓存保留原始读回时间，不能冒充本帧新读取的参数。其他型号未声明该能力时保持原采集契约，不删除其必需的波形描述信息。

纯监测允许参数修改和 Auto，控制组暂停后续曲线请求，修改完成后下一帧重建快照。仅连续采集/记录期间由公共会话和 UI 同时锁定参数、Auto、范围/设置读取，包括读帧间隙和停止后的在途写盘收尾；本地采集节奏和软件标记仍可调整。拒绝请求不得访问仪器。停止记录后恢复编辑和纯监测。此锁只约束本软件，不远程锁仪器前面板；监测时前面板改动须主动“刷新参数”，记录时须先停止记录再改。无轮询不能声称自动发现外部参数变化。

以下约束适用于现有及后续优化。公共层已经提供通信计时与读取机制，DSA815 声明支持轻量模式；其他型号未声明时保持原采集路径。

- 先分别统计每帧查询次数、各类命令耗时、传输/解析/调度/写盘时间，再确定瓶颈。UI 定时器、VISA 超时和仪器扫描时间是不同概念；降低超时不会使仪器回复更快。
- 区分曲线读取、设置同步与诊断快照。缓存前必须由型号包列出坐标、单位、有效性及元数据依赖，给出刷新与失效路径；明确软件能检测的修改和需用户主动刷新的前面板修改。缓存帧标为 `cached`，旧快照不得无标记地附作本帧实际配置。
- 优先利用厂家确认的成组读回或波形描述减少往返；不能套用同厂家另一型号的命令。命令队列、分号复合查询、多个在途请求分别验证，不能混为一种优化。同一设备仍使用会话串行边界，不通过第二连接并行读取来绕过锁。
- 传输或二进制优化须验证完整消息边界、实际单位、字节序、截断及超时行为。TCP 端口和批量能力必须有型号依据；不因新传输更快就允许自动重发写入。为基准改变数据格式仍须备份、恢复和核对。
- 固件读回的格式/字节序还须用冻结的同一帧对比文本与二进制实际编码，不能只凭数值有限就认定正确。发现固件差异时，适配规则限定型号、硬件与固件，并保留设置值及实际解码依据；禁止解析失败后自动试另一字节序。硬件报告须先检查测量质量，保留会话返回的原始错误，不能把诊断用空帧作为正常数据统计。
- 性能对比保持配置和测试条件可比，记录耗时分布、有效帧数量与失败情况；改变传输、格式和查询策略时分别测量。传输完成率不自动等于新扫描率。研究报告区分公开实现、项目推断及实机结果，开源引用固定版本。

上述经验的源码与厂家依据见[DSA815 通信研究](../../src/lab_control/instruments/devices/rigol_dsa815/communication-research.md)。共性机制放公共层，型号缓存依赖和协议留在型号包。

## 完整保存与兼容接口

- 公共存储层统一生成目录：根目录来自持久设置，按单设备/批量、电脑本地日期、毫秒开始时间与设备身份分层，模式仅存元数据。不可变保存上下文必须在接受记录或单帧保存时建立，并贯穿排队读取、二进制写盘及 CSV 转换；跨午夜和设置变化不能重新计算路径。上下文构造不得创建文件，批量接口显式共用批次上下文，不根据同时连接的设备数推断批量任务。格式见[数据模型](../data/data-model.md)。
- 连续记录开始先准备目录、说明和 `_raw/recording.json`，失败须恢复原任务状态、模式和参数锁，原错误向调用者报告，不能静默更换根目录。无有效帧即停止时保留说明、清单及零帧摘要。单帧目录按保存操作时间命名，原始 snapshot/NPZ 保留原帧时间和来源。修改数据根目录不迁移库存、日志、实机档案及历史记录；真实与 Mock 的设置和数据分别隔离。
- 监测记录的目录准备使用两个后台工作线程，每个活动设备最多保留一个准备任务，重复点击复用同一 Future；队列随活动设备数有界，不按帧积压。接受请求时固定保存上下文并锁定该设备参数，磁盘准备不占 Qt 主线程或公共监测锁；期间该设备不提交新帧，其他设备继续监测。停止、断开或退出使准备结果失效，已经创建的零帧记录完成收尾后才释放锁。界面经控制器使用 `background=True` 和 Future；原同步服务接口仍等待准备成功或抛出原错误，调用者不得在持有调度锁时等待 Future。
- 每批记录完成后独立发布结果，保留最近 32 批摘要并写审计日志。旧批 CSV 转换迟于下一批失败时，仍显示错误及原批目录，不覆盖新批记录状态；不能只依赖当前任务的 recorder 判断历史保存成功。
- 新记录使用布局版本 2：原始数据、完整时间及恢复文件位于 `_raw`，顶层为中文说明和面向 Excel／Origin 的分析 CSV。导出根据通用测量结构选择标量宽表或多帧曲线，保留每通道实际坐标、缺失值和时间来源，不通过插值或软件间隔制造同步。分析文件按 100 万行／100 MiB 或列结构变化轮转，与数据库分段独立；曲线帧索引和所有输出共同检查点提交。保持分块写盘、转换进程并发上限、错误隔离及二进制收尾后的锁释放，不在仪器线程运行格式转换。旧布局和旧详细 CSV 检查点仍可恢复。
- `AcquisitionRequest.consistency` 默认 `full`。公共监测仅对声明 `supports_live_acquisition` 的适配器发送 `live`，独立运行有独立上下文编号。DSA815 的 `live` 首帧完整核对，稳定帧只查询轨迹。声明 `supports_stream_acquisition` 的型号在连续记录时接收 `stream` 和本次运行的非空 `context_id`，只允许被动读取；首帧完整核对后沿用启动快照。未声明能力的型号保持原路径；`legacy` 不凭空增加校验承诺。
- 适配器可提供 `invalidate_acquisition_context(reason)`，会话在设置执行前及异常时通知；重连使用新适配器。型号读取需自行处理前面板变化，并在返回结果中保留每个设置的原始读回时间。`acquisition_readings` 只发布本次新核验的字段，不能刷新缓存字段的新鲜度。
- 声明 `supports_control_updates` 的型号自行冻结设置前快照、核验修改项和关联项，再通过可选 `ApplyResult.control_update` 返回读回、受影响范围及完整性。无关字段沿用原值和原始时间，来源为 `control_cache`，公共层合并到新配置版本；失败不发布成功覆盖，不重放写入。依赖由型号声明，公共界面不推断；旧型号仍先失效、保守刷新。
- 9404M/DHO924 的已知局部控制保留本次运行上下文，后续首帧为 `cached`，不因配置版本递增全量回读；型号仍核对每帧自身描述。9404M 仅对受影响字段在首帧之后再次核对，并恢复稳定指纹；DHO924 用 PRE 与新设置的对应关系及 DATA 前后 PRE 校验。Auto、主动刷新、缓存缺失、未知依赖、异常及新运行批次走完整核验；显式 `full`/完整存储的契约不变。
- 控制完成以 Qt 排队通知串行推进，结束后唤醒监测；已核验的覆盖直接发布给控件，不追加页面全量读取或立即空闲同步。后台低频同步仍保留原有错峰期限，记录及排空锁不变。
- 示波器水平/垂直拖动允许明确标注为“估算”的临时显示变换。可选 `scope_display.vertical_offset_sign` / `horizontal_position_sign` 由型号提供，公共图形层不得猜厂家方向；缺少方向时不预览该偏移。预览只改变曲线场景变换和视窗，不替换不可变帧、原数组或保存元数据。松手后按配置版本等待有效帧接替，旧帧或无效帧不能清除待实测状态；取消/失败恢复真实显示。
- 界面“保存当前帧”固定绘图组件最后实际显示的不可变帧及通道选择，通过 `export_displayed_frame` 后台导出，不查仪器、不替换为服务里的更新帧、不暂停监测或锁参数。原 `capture_and_export` 新读帧接口保留兼容；不再由界面保存按钮调用。写盘进行中禁止同设备重复提交，失败不重试，退出排空已授权写盘。
- 显示快照允许导出通过数据结构/有限值/质量检查的 `live` 或 `cached` 帧，保留原始时间、设置来源、校验级别和完整数组；它不等于完整采集验收。暂停或参数改变后仍显示的旧帧可导出自己的配置，不能拼接新的参数。连续记录仍拒绝 `live` 及缺少本次记录上下文/配置来源时间的 `cached` 帧；不能把显示导出的宽松来源规则用于自动记录。
- 公共诊断使用线程局部计时，不持有轨迹数据；每个会话保留最近 120 帧，5 秒输出汇总。详细查询统计通过 `LAB_CONTROL_IO_DIAGNOSTICS=1` 显式开启，记录命令类别、长度、耗时及错误类型，不记录回复内容。
- 流读取明确区分 exact 与 read-up-to。VISA 原生文本利用终止符结束读取，TCP 使用接收上限，串口只读取已到达的剩余数据；仅支持定长读取的句柄保留保守路径。二进制按声明长度读取，文本优化不能改变二进制消息边界。
- 支持 read-up-to 的流在消息开始即整块读取，避免每条短回复额外读取一个字节；文本续读只重新检查终止符可能跨块的重叠部分。二进制中的 CR/LF、后续消息和短读仍必须完整保留。原生 TCP/VICP 使用 `TCP_NODELAY`；不把某个驱动或操作系统的默认值当成实测结果。
- 合并查询是型号显式选择的协议能力。公共 `transport/scpi.py` 只提供简单无参数查询的绝对路径拼接和精确字段数量检查，不决定哪些型号支持。型号须验证回复顺序、结束边界和各字段解析；字符串、二进制、多行表格和设置命令不得混入标量查询组。合并不保证仪器原子快照，仍需前后核验。失败不改成逐条重发，不增加第二个在途事务。
- 诊断中的 `queries` 统计发送/接收事务；型号可另报 `logical_queries` 说明合并的 SCPI 子查询数。适配器补充的元数据可随完整保存保留，实际发送/读取/整帧计时由公共层记录，不能被型号覆盖。
- 文本行结束不等于回复结束。多行表格需要协议结束标志或厂家明确的完整性规则；不能靠空闲超时、固定猜测行数或只读首行来拼接回复。某传输缺少可验证的边界时，型号在发送前声明该查询不可用，不污染下一条查询。连接、备份和恢复必须分别在候选传输上预检，不继承另一资源的成功状态。
- 分组恢复结果带所属阶段。下一组再次修改仪器时，上一组的空差异或成功快照只能留作历史，不能继续标为当前最终状态；失败时明确列出最后可确认状态与未核实项。

## 必须覆盖的回归

1. 设置只执行一次；随后配置变化的帧被丢弃，恢复有效帧后继续显示，草稿和连接不丢失。
2. 持续变化有明确上限；单次读取不变成自动重试。未知或损坏回包不能被“暂态”规则吞掉。
3. 逐帧记录与旧 API 独立选帧、运行中修改、停启记录、慢读取、慢写盘、写盘失败、停止排空和设备隔离。
4. 编辑间隔零仪器写入、零自动记录；实际刷新显示与帧到达一致；设备切换恢复各自偏好。
5. 用户可见入口合并时，仅保留一个清楚的主操作；其他类别原有控制入口不受影响。
6. 跨信号源、电源和频谱仪验证低频同步、监测时零独立参数轮询、停止后恢复、错峰启动与长时间暂停后无突发补查；主动参数读回和测量状态采样不被误限速。
7. 监测可编辑、记录及在途保存期间锁定；记录启动与控制组互斥。缓存监测长时间运行不自动查询参数，主动刷新、Auto 与未声明依赖的控制使下一帧完整核对；支持局部覆盖的型号核验修改项及关联描述，新批次不继承旧上下文。缓存时间不变，来源不完整或仅来自纯监测的帧不得冒充连续记录帧；手动显示快照保留原来源并单独验证。
8. 保存设置重启恢复；路径非法、不可写及失效时保留原设置或撤销启动。覆盖跨午夜、排队延迟、记录中改目录、无有效帧、重复提交、批量共享目录和设备间不覆盖。旧格式可读、旧分段可转换，元数据测试工厂不写曲线，设置页在紧凑窗口仍可操作。
9. 跨型号验证超时/断线/坏帧重连、原批次续存、长期离线退避、停止优先、单次读取不重试、身份冲突、初始化不重放、写盘错误、事件先于 Future 完成的竞态及有限流续接。模拟通过与实机通过分别留档。

Mock 验证调度和错误分类，不证明实机吞吐量或自动设置的收敛时间。实机改变设置前仍须备份，遵循[实机记录规范](../testing/records.md)。

## 后续型号优先二进制

用户已确认二进制优先。新型号应核对厂商命令、编码、字节序、块长度和坐标缩放，验证短读、截断、有限值、单位及实机正确性后，在型号包声明 `prepare_acquisition()`。公共连接层只在型号/序列号/固件约束和资产占用核验后调用；不在扫描或身份探测中写入。未声明的型号保持原行为，不根据品牌猜命令，不认为所有二进制都为 REAL32。

初始化须读取原格式及字节序、只在必要时设置、读回确认并记录前后状态。失败保留已尝试写入及最后可确认状态，不重发或换协议。只读预检、硬件备份和指定历史恢复显式传入 `configure_acquisition=False`；默认行为不能破坏这些入口的零写入承诺。DSA815 已启用此路径，其他型号以各自验证为准。正常断开不恢复格式；实机对比批次仍恢复其测试前格式。

硬件性能入口必须在任何连续采集开始前替换或禁用完整曲线导出及 create_recording 工厂；只替换旧 export 不再覆盖连续记录。不能把“返回路径列表”的采集保存入口当成只返回数据的读取。元数据记录器只留时序、长度及哈希；完整文件保存验证使用隔离 Mock。测试入口同样须检查无额外数据目录产生，意外产生文件时按批次/身份/哈希核对，仅清理本批次误生成文件，保留失败及清理证据。检查“监测期间无独立查询”时，在同一调度锁下启动计数和监测，停止前关闭自动同步；收尾后的合法低频同步不能冒充采集期间的查询。

元数据专用记录工厂接收并保留保存上下文，但使用 `Recording(..., prepare_storage=False)` 跳过目录及清单创建，同时继续拦截分段写入和 CSV 转换。只创建上下文不产生曲线文件，不会预先创建采集数据目录。

## 频谱与示波器视图稳定性

示波器紧凑网格优先采用每个 Measurement 的可选 `scope_display` 版本 1 元数据：单位/格、参考值、秒/格和时间中心，由型号包提供。公共层按 `(原始值 - 参考值) / 单位每格` 映射八格纵向窗口，横向为时间中心 ±5 格；9404M 的参考值为负 OFST，时间中心为负 TRDL。所有字段须有限、尺度为正、单位一致、水平窗口可表示。缺少元数据的旧型号才沿用下述通用适配规则；无效元数据不能替换有效显示。保存始终使用完整物理坐标和样本。

9404M 显示元数据来自本帧已核验的快照，缓存帧沿用原快照时间；WAVEDESC 仍逐帧解码原始物理数组，不用缓存 gain 解释样本。配置写入及主动刷新在控制组内串行完成，读回相关标量后再采集；关闭通道使用停止并排空旧读取、修改核验、以准确通道集合重新开始的顺序，不能调用累加式 start 来移除通道。全部关闭后保持软件停止。

频谱以及缺少可靠显示元数据的示波器，在对应监测页复用一次性适配策略。首次有效帧、设备/会话/配置版本变化、通道选择及主动刷新后的实际参数或坐标单位变化时，以完整曲线范围设定 Y 轴并上下各留 10% 余量；X 轴两侧各留 2%，恒值采用非零跨度，单点波形显示点标记并保留原时间坐标。时间戳、记录元数据、帧序号和软件节奏不触发适配。示波器正常水平原点抖动不触发适配，实际水平参数变化通过配置快照判断。

范围必须在显示降采样之前由完整数组确定，防止短时基波形在初始秒级视图中被峰值降采样为空。稳定示波器帧只更新数据，不重复求完整幅度范围。普通更新禁用持续自动缩放，保留用户视图；手动适应直接使用最新已显示帧的完整数组，执行一次，标记不参与范围计算。无效帧不替换已显示帧，也不消耗待适配状态。显示降采样不改变保存数组。该规则不改变其他类型曲线的自动缩放。

绘图库原生 Fit 入口也必须遵守上述策略：频谱与旧波形走一次性适配，仪器网格隐藏原生按钮且所有恢复入口使用帧自身的仪器窗口。网格 ViewBox 防止持续自动缩放或其他范围变化将 −4～+4 格压缩；不从波形幅度推导仪器档位。各设备监测页复用同一实现，总览不创建图形视图。

记录按钮与卡片描边只读取现有任务快照，由公共 UI 状态转换维护：`recording_preparing` 为准备中，`recording` 为记录中，停止接收后且 `recording_state.binary_done` 未完成为收尾中，二进制完成后为未记录。准备与收尾按钮禁用，可停止监测取消准备；记录/收尾均保留固定宽度红框。后台 CSV 转换不延长红框或参数锁。状态展示不得额外查询仪器或自行改变流水线生命周期。总览描边表示本设备的记录任务，不保证每张卡片所选通道都包含在记录集合中，悬浮提示说明保存范围以任务为准。
