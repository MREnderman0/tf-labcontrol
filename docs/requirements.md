# 实验室多设备控制软件：需求说明

版本：v1.5（兼容层与实测入口）
日期：2026-09-23
状态：0.3.0 已实现兼容层、真实总览、分类控制、实时监测与 CLI/Python 实测入口；实机验证待现场完成。本文保留长期产品需求，当前页面与任务边界以[设备管理](requirements/device-management.md)、[实时监测](requirements/realtime-monitoring.md)为准，实际设备能力以[能力矩阵](generated/capability-matrix.md)为准。自动实验、阈值告警与数据处理仍未实现。

## 1. 文档约定

- **已确认**：用户已经明确的需求或交互规则。
- **建议方案**：用于后续设计的实现建议，不代表范围已经冻结。
- **待确认**：需要结合具体设备、实验流程或使用习惯继续讨论的内容。
- 本文是持续更新的总需求入口。附件《环境实验软件需求》中的设备清单、数据模板和功能描述已归档到 `docs/device-research-index.md` 及分层文档；附件中的历史日期和空白指令表不作为当前交付承诺。

## 2. 产品目标与第一版边界

软件是运行在 Windows 上的实验室多设备控制上位机，使用 Dashboard 方式管理设备、采集数据、实时监测、处理结果并记录操作过程。

### 2.0 技术栈和实现边界

- 推荐技术基线为 Python 3.12+、PySide6 和 Qt Widgets，使用自定义 QSS 实现深色 Dashboard。PySide6 只负责 UI，设备协议通过应用层接口接入。
- 第一版采用 Python 模块化单体，不拆微服务；6–20 台设备由独立 Qt worker 管理，设备 I/O 不在主线程执行。
- VISA 设备使用 PyVISA 配合 NI-VISA；非 VISA 设备使用 PySerial、TCP 或厂商 SDK 独立适配。pyvisa-py 作为受控环境中的可选后端。
- pyqtgraph 用于波形、频谱和趋势图；NumPy/SciPy 用于 FFT、统计、滤波和拟合。
- SQLite 保存设备、槽位、预设、任务、阈值、日志和 HDF5 文件索引；HDF5 保存波形、频谱和高频时序；NPZ 保存小型中间数组；CSV 用于导出。
- 日志使用 Python `logging` 和 structlog；应用层另维护结构化操作审计事件。
- 使用 uv 管理依赖和锁文件，后续以 PyInstaller one-folder 打包 Windows 应用。VISA Runtime、USB/串口驱动和厂商 SDK 属于部署前置条件。
- 第一版不接入 OpenTAP、不创建自动实验流程；自动步骤后续在采集协调器之上评估。
- 当前已提供 PySide6 设计演示壳子，用于评审信息架构和视觉方向；壳子只使用内存演示状态，不连接真实设备、不保存实验数据。
- 设计壳子不代表真实 VISA/串口、设备适配器、采集和数据处理已经完成。
- 技术栈和开源组件的引入边界见 `docs/architecture/technology-stack.md`、`docs/architecture/system-architecture.md` 和 `docs/open-source-references.md`。

### 2.1 已确认的第一版约束

- 第一版按一次实验同时在线约 **6–20 台设备**设计。
- 第一版支持多设备同时连接和联合采集。
- 第一版以手动控制设备和联合采集为主，自动实验流程后续再做。
- 软件支持“电子学模式”和“光学模式”。两种模式共用设备连接、采集、监测、处理和日志的通用逻辑，但使用不同的设备、功能块、监测对象和数据类型。
- 电子学模式与光学模式的预设、设备绑定、Dashboard、采集配置、处理配置和数据记录分开保存。
- 记录或控制进行中锁定模式切换；纯监测时允许切换视图与适用性，不停止后台任务。
- 电子学模式和光学模式使用独立的配置目录和实验数据目录。
- 设备扫描可以发现全部设备，设备管理总览始终显示全部设备；当前模式只影响槽位匹配、控制入口和采集源。
- 与当前模式不兼容但已连接的设备保持会话并继续显示；不能新绑定或发起当前模式控制/采集，已有纯监测继续。切回原模式后恢复适用性和绑定，不自动发送命令。
- 实时监测可以只查看；用户显式“开始记录”或“保存当前数据”后才保存实验文件。
- 目标设备类别包括：信号源、电源、示波器、频谱仪、光功率计、万用表、网络分析仪、相噪仪、光谱仪、温控设备、电子负载和泵浦驱动。
- 每类设备的最低打通标准为：扫描、连接、基础控制、状态读回和基础采集。
- 希望使用通用 VISA 控制层；串口等非 VISA 设备保留独立通信适配入口。
- 初版不要求覆盖厂家手册中的全部高级功能，超出基础范围的能力按型号逐步扩展。

### 2.2 暂不冻结的范围

- 所有型号的实机固件、实际资源地址、接口选件和现场驱动版本。
- 各设备类别的系统固定功能块完整清单。
- 数据处理的顶部子菜单、首批算法和数据格式。
- 典型实验流程、采样速度、持续时间和同步精度。
- 预设导入、导出、版本和权限。
- Windows 版本、离线部署和 VISA/设备驱动安装策略。

## 3. 总体信息架构

### 3.1 左侧一级导航

左侧栏固定为六个一级模块：

1. 设备管理
2. 数据采集
3. 实时监测
4. 数据处理
5. 操作日志
6. 系统设置

设备连接会话、采集任务和后台数据流不随页面切换而销毁。切换左侧模块时，设备连接和正在运行的采集任务继续保持。

### 3.2 已确定的顶部子菜单

| 左侧模块 | 顶部子菜单 | 状态 |
| --- | --- | --- |
| 设备管理 | 总览与全部设备类型（含光学及分析类） | 0.3.0 已接通 |
| 数据采集 | 采集配置、采集中、历史记录 | 已确认 |
| 实时监测 | 总览与全部设备类型 | 0.3.0 已接通 |
| 数据处理 | 待定 | 保持草案 |
| 操作日志 | 全部日志、设备操作、采集与处理、异常与告警 | 已确认 |
| 系统设置 | 软件设置、数据存储、通信设置、日志设置 | 已确认 |

### 3.3 电子学模式与光学模式

软件提供一个全局运行模式开关：

- 电子学模式
- 光学模式

两种模式共享设备发现与连接、功能块绑定、采集任务、实时监测、数据处理、操作日志、配置预设和系统设置的通用流程。模式只替换具体的设备和能力集合，不复制两套软件流程。

模式相关内容包括：

- 可见的设备类别和设备适配器。
- 系统固定功能块，例如电子学模式的信号源/电源需求或光学模式的光源/探测器/温控需求。
- 实时监测对象，以及曲线、波形、频谱等数据类型。
- 采集任务中的设备、通道、采样配置和触发配置。
- 数据处理工具、参数和结果格式。
- Dashboard 磁贴、槽位绑定、监测规则和阈值配置。

当前模式下不适用的设备、功能块和数据处理能力不进入当前模式的绑定候选、控制入口或采集源，但设备本身仍在设备管理总览中可见。已连接但不兼容的设备保留连接会话，切换回原模式后恢复适用性和原有槽位绑定，但不自动发送控制命令。

模式只能在没有运行中的采集和控制任务时切换，切换前需要二次确认；不能造成设备命令或数据记录跨模式混用。模式切换行为本身写入操作日志。

## 4. 设备管理

设备管理负责设备池、发现、连接、通信配置和功能槽位绑定。仪器工作参数由对应的设备类型控制页或实时监测页处理。

设备类别卡片和功能块清单由设备注册表和当前模式能力共同决定。总览显示两种模式的全部设备；另一模式的设备不参与当前模式的槽位匹配、采集和监测。

### 4.1 总览页

总览采用“类别卡片 + 详情抽屉”，始终显示设备注册表中的全部类别，即使数量为零。卡片至少覆盖信号源、电源、示波器、频谱仪、光学测量、万用表/网络分析仪/相噪仪、温控/负载/驱动和未知设备。

页面顶部显示扫描设备、最近扫描时间、扫描进度、发现/识别/连接/未知/异常数量和失败汇总。类别卡片显示已发现、已识别、已连接、未连接、未知/待补信息、异常和已绑定数量。

点击类别卡片后打开详情抽屉，支持按类别、连接状态、识别状态和适配器状态筛选，并查看厂家、型号、序列号、固件、主/备用资源、传输类型、驱动/VISA/SDK 状态、身份可信度、适配器能力、功能槽位、最近扫描和最近错误。

抽屉支持连接、断开、重连、刷新身份、诊断、显示名修改和槽位分配。设备管理总览不承担完整仪器控制面板；扫描期间保留已有卡片、设备行和连接状态，不用空状态替换页面。

### 4.2 扫描和识别

扫描、会话保护、资源合并和失败处理以 [`device-discovery-and-overview.md`](requirements/device-discovery-and-overview.md) 为准。扫描由后台 `DiscoveryService` 执行，先获取活动会话快照，再枚举 VISA、COM 和 SDK 资源。

- 活动会话正在采集或控制时只使用缓存；空闲会话的身份刷新排入原 worker，不新开第二个句柄。
- 非活动资源只执行适配器声明安全的官方身份 API 或 `*IDN?`；未知协议只登记，不遍历命令。
- 结果同时保存发现状态和连接状态。资源未出现只标记 `stale`，不能直接将设备会话改为断开。
- 结果至少包含：发现入口、类别、厂家、型号、序列号、固件、资源地址/COM 口、传输类型、身份可信度、适配器、连接状态、发现状态、异常状态和当前槽位。
- 同一物理设备的多个 USB、LAN、GPIB 或 VISA 资源保留并合并；无序列号时不能仅凭 COM 号、IP 地址或 GPIB 地址确认型号。
- 无法自动识别时显示“未知设备”，允许用户补充类别/适配器，但仍禁止危险能力。
- 扫描不自动连接、不打开输出、不改变设定值、不执行预置；连接失败要显示端口占用、驱动缺失、超时或参数不匹配等可理解原因。

### 4.3 设备类型页

设备管理顶部的信号源、电源、示波器、频谱仪和温控页用于按类别查看设备和功能块，便于选择连接设备及完成接入配置。

设备工作参数，例如示波器的时基、触发、采样设置，以及频谱仪的起止频率、分辨率等，放到对应的控制页或实时监测页操作。

## 5. 功能块与设备绑定

### 5.1 功能块模型

功能块是实验语义上的固定需求位置，例如：

- 移频信号源
- AOM 控制信号源
- 偏置电源
- 温控通道

功能块由系统定义，用户不能在配置预设中任意新增、删除或排序。不同设备类别的固定功能块清单待结合首批实验确定。

每个功能块必须提供设备选择框，第一项固定为：

```text
请选择设备
```

该选项表示当前未绑定设备。功能块仍然保留并显示其预留配置，但不会向任何设备发送命令。

### 5.2 绑定规则

- 一台物理设备同一时间只能绑定一个功能槽位。
- 设备可以在不同实验或不同阶段重新分配到另一个功能槽位。
- 功能块的设备选择框只显示已连接、同类型且未被其他槽位占用的设备，以及“请选择设备”。
- 设备正在执行采集或控制任务时禁止更换槽位。
- 更换槽位需要二次确认，并写入操作日志。
- 设备换槽后，旧功能块立即显示“未绑定”，但保留原有配置。
- 未使用的空槽位不阻塞采集；本次采集实际使用的功能块必须完成设备绑定。
- 一个预设可以保存多个未绑定功能块，便于后续补充设备。

### 5.3 设备池与功能槽位的关系

物理设备池记录真实设备及其连接状态；功能块记录实验需要的设备角色。二者分开保存：

```text
物理设备：SG-01 / 厂家 / 型号 / VISA 地址 / 已连接
功能块：移频信号源 / 当前绑定 SG-01
```

设备更换时只改变功能块的绑定关系，不复制或修改物理设备的身份信息。

## 6. 配置预设与运行状态

### 6.1 配置预设内容

配置预设保存完整实验工作区，包括：

- 所属模式（电子学或光学）。
- Dashboard 布局。
- 固定功能块与设备绑定关系。
- 未绑定功能块及其预留配置。
- 磁贴类型、显示单位、刷新频率和显示参数。
- 监测规则。
- 采集参数。
- 数据处理参数。

当前 Dashboard 使用内容宽度自动排布卡片，支持添加、移除、改名与顺序调整；不提供列数选择、自由拖拽或缩放。按模式保存配置，不保存计算出的列数。设备类型页使用能力表单，不允许通过预设扩展设备真实能力。

### 6.2 加载和修改预设

加载预设时：

- 只允许在相同模式下加载；模式不一致时提示用户切换模式或选择其他预设。
- 恢复功能块绑定、Dashboard 布局、采集参数、监测参数和处理参数。
- 检查绑定设备当前是否存在、已连接且能力匹配。
- 对缺失、未连接或型号不匹配的设备给出提示，并保留功能块配置。
- 不自动连接设备。
- 不自动打开输出、不自动改变设定值、不执行危险操作。

实时监测页点击“应用”后：

- 立即向设备下发参数。
- 记录操作前值、目标值、设备、功能块、结果和错误原因。
- 更新当前预设。
- 另存为其他预设必须由用户主动执行。

运行时连接句柄、会话对象、临时任务状态和瞬时通信状态不写入预设。

电子学模式和光学模式使用分开的预设命名空间；同名预设也不互相覆盖。

## 7. 数据采集

### 7.1 页面入口

数据采集顶部子菜单暂定为：

- 采集配置
- 采集中
- 历史记录

### 7.2 采集规则

- 支持选择多个设备、功能块、通道和测量量进行联合采集。
- 采集开始前可预览实时数据，但不自动形成实验记录。
- 采集记录带有所属模式；电子学数据和光学数据不能写入同一条模式记录。
- 点击“开始采集”后创建实验记录，并保存设备身份、功能块绑定、关键配置、时间和数据来源。
- 采集任务支持开始、停止、运行中、完成和失败状态。
- 未使用的空功能块不阻塞采集；实际参与本次采集的空功能块必须先绑定设备。
- 采集频率、设备内部采样率和界面刷新频率分别定义。
- 多设备软件轮询不默认代表硬件同步；同步精度和触发方式待具体实验确认。
- 设备超时或断连时不伪造有效数据，数据质量和连接异常必须显式标记并写入日志。

自动实验步骤不属于第一版采集任务范围。

## 8. 实时监测

- 实时监测使用可配置 Dashboard，支持绑定数据源、调整顺序、按宽度自动排布和按模式保存；无手动列数、拖拽或缩放。
- 设备类型页使用固定功能块，监测页负责跨设备的数据展示和必要的工作参数调整。
- 监测页按设备能力提供控制入口，例如示波器和频谱仪的采集参数；不支持的能力不显示为可用控件。
- 起止频率、分辨率、时基、触发等参数点击“应用”后排入原设备 worker，当前读取结束后执行，并写审计；错误只暂停目标设备。
- “开始监测”只查看数据；显式“开始记录”或“保存当前数据”才写实验文件。
- Dashboard 只显示当前模式适用的数据源和功能块。
- 实时监测顶部子菜单为总览与各设备类型，具体以实时监测设计为准。

## 9. 数据处理

数据处理使用统一数据模型，不依赖具体厂家型号。首批算法和顶部子菜单暂不冻结。

候选能力包括：历史采集查看、区间裁剪、基本统计、平滑/滤波、FFT、峰值/带宽分析、多通道对比、公式运算、图表和数据导出。

处理结果需要记录来源数据、处理参数、单位和结果时间，便于复现和追溯。

## 10. 操作日志

顶部子菜单：

- 全部日志
- 设备操作
- 采集与处理
- 异常与告警

建议记录：

- 扫描、连接、断开和重连。
- 设备绑定、换槽位和预设加载。
- 参数修改前后值、应用结果和设备响应。
- 输出启停、采集开始/停止、数据处理和导出。
- 超时、断连、识别失败、数据质量异常和后续阈值事件。

每条日志至少包含时间、设备、功能块/任务、操作、结果和错误原因。高风险批量操作需要二次确认，并显示逐台执行结果。

## 11. 系统设置

顶部子菜单：

- 软件设置
- 数据存储
- 通信设置
- 日志设置

第一版设置范围包括：主题和界面偏好、默认数据路径、实验记录保存策略、VISA/串口扫描配置、通信超时、重连策略、日志级别和日志保留策略。

系统设置还包含电子学/光学模式开关。模式切换前检查采集任务和控制任务是否为空闲；非空闲时禁止切换，空闲时要求二次确认并记录日志。切换不自动重连设备、不自动打开输出、不自动下发恢复命令。

电子学模式和光学模式分别保存预设、Dashboard、功能块绑定、采集/监测/处理参数和实验数据；软件主题、通用扫描机制和日志基础设置可继续作为公共设置。

用户、角色、权限和审计设置暂未纳入第一版确定范围。

## 12. 统一设备与数据模型建议

### 12.1 设备对象

设备对象至少包含：

- 稳定设备标识。
- 设备类别、厂家、型号、序列号。
- VISA 资源名或 COM 信息。
- 通信协议和适配器标识。
- 连接状态、识别状态、异常状态。
- 当前绑定功能块（允许为空）。
- 已验证的能力集合。

### 12.2 控制适配层

建议分为四层：

1. 界面和实验语义：移频信号源、偏置电源、温控通道。
2. 设备类别能力：设定频率、读取电压、读取温度、获取波形等。
3. 型号适配器：将统一能力转换为具体 SCPI、VISA 或厂商 SDK 调用。
4. 通信传输：VISA、串口、TCP、Modbus 或厂商 SDK。

设备 I/O 在后台执行；同一设备的命令和响应按队列协调，避免并发操作串读响应。

### 12.3 数据类型

统一数据模型需要支持：

- 标量/时序点：时间、测量量、值、单位、质量状态。
- 时域波形：时间轴或起点/间隔、样本数组、幅度单位。
- 频域轨迹：频率轴、幅度数组、幅度单位和必要的参考信息。
- 配置/状态：设定值、读回值、设备状态、时间和来源。

必须区分设定值、测量值和处理结果；超时、断连、无效值和陈旧值不能用零值冒充有效数据。

## 13. 第一版验收基线

### 13.1 设备接入

- 能扫描 VISA 资源和 COM 口。
- 能显示已识别和未知设备。
- 能选择设备并连接、断开、重连。
- 能配置基础通信参数并显示错误原因。
- 能查看设备身份、连接状态和当前功能块。

### 13.2 统一控制和采集

- 每个已确认设备类别至少有一个实机或可验证适配器完成基础控制、状态读回和基础采集；待补型号先完成盘点门槛。
- 同类设备通过统一功能入口操作，型号差异由适配器处理。
- 6–20 台设备可同时在线管理。
- 支持按类别查看、按预设绑定和批量连接/断开。
- 高风险批量操作有二次确认并显示逐台结果。

### 13.3 预设、监测和日志

- 预设能保存布局、功能块绑定、未绑定状态、采集/监测/处理参数。
- 加载预设时能提示缺失设备，不自动连接或开启输出。
- 监测页能调整支持的设备参数，点击应用后立即下发并记录日志。
- 未使用的空功能块不阻塞采集，实际使用的空功能块阻止任务开始。
- 设备换槽时有任务锁定、二次确认、旧槽位清空和日志记录。
