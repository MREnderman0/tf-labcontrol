# 后台检查静默显示验收（2026-09-24）

本轮仅使用隔离 Mock、正式 Qt 页面和会话 worker，没有访问真实仪器或改变真实设备设置。修复对象是正常后台参数检查期间，信号源顶部与设备下拉框不断交替显示忙碌文字的问题。

## 显示规则

会话快照新增布尔字段 `backgroundRead`：仅在静默 `read_settings` 实际执行期间为真，结束或失败时清除。内部 `connectionState`、`activeTask`、队列、硬件占用与操作限制保持原有语义。

统一的 UI 显示规则只将“单独后台参数读取”的忙碌状态映射为“已连接”，任务文字保持空闲；设备下拉框、信号源顶部和设备池状态／提示／筛选共用此规则。正在监测、记录、分组控制、有待执行控制或其他排队任务时不隐藏进度。异常状态优先于后台标记，初始未读取、数据过期和无效读回仍由原有同步状态提示。

## 自动化证据

[信号源同步 UI 测试](../../tests/integration/test_signal_sync_ui.py) 使用可暂停的 Mock 读取验证：

- 连续三轮读取，在开始、执行中与完成后反复刷新；连接文字、下拉选项、设备池选中项、键盘焦点和未应用草稿保持稳定，没有下拉选项重建、选择事件或任务通知。
- 后台执行期间内部仍为 busy，资源租约仍持有；不带排空选项的直接断开请求仍被拒绝。设备池“断开／重连”可等待单个后台读取结束后释放连接，避免按钮在检查期间短暂禁用；主动控制、分组控制和采集继续禁止断开。忙碌筛选不收录单独的后台读取，已连接筛选保持可见。
- 用户手动读取、应用修改和连续采集实际进入 worker 时仍显示任务进度。
- 超时与无效读回仍显示异常，结束后后台标记清除；断开后清空设备选择。额外覆盖异常、连接中、监测、记录、待应用控制及排队任务的显示优先级。
- 既有回归继续覆盖首次同步、过期数据、输出保护、设备／模式切换、范围校验及其他类型设备选择。

本轮没有布局改动；证据为真实 Qt 控件及会话生命周期断言，不将其描述为 Windows 实桌面人工检查。
