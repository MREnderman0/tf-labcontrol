# 公共采集与 DSA815 快速监测软件验收

日期：2026-09-25。实机身份、地址和各组性能数字只保存在正式运行目录，本页记录软件与隔离界面验证。

下方各阶段按实施先后保留。当前契约见文末“采集、显示与保存流水线”，此前的 23 次查询、30 秒参数刷新及逐帧文件导出是历史基线。

## 实现及验证

- 公共流读取区分定长与分块，保留仅支持 exact 的旧句柄；真实 TCP 流、VISA 句柄替身、串口 GPD4303S 和 VICP 覆盖消息边界及异常传播。
- 公共诊断不保存载荷，查询、读、写分别计数；120 帧容量和详细诊断的脱敏边界有测试。
- DSA815 协议测试验证完整 45 次、稳定轻量 23 次查询；缓存过期/失效、前面板配置变化、旧时间保留、截断和无效数据均覆盖。
- 保存回归验证在读取前决定 full、慢写盘不形成积压、手动排队一次完整读取、重复请求拒绝、失败零旧帧保存，以及关闭时排空已授权任务。
- 连接偏好测试验证资格缺项、性能门槛、环境/固件/版本变化、显式主资源和地址变化。候选生成不伪造 Socket 身份核验结果。
- Qt 测试验证“采样并保存”标签、完整读取、计时悬浮说明，以及更新时草稿和输入焦点保留。实时监测入口沿用已确认请求的通道与点数，避免保存时悄悄回到默认值。
- 最终全项目回归 1191 通过、1 跳过（包含后续 Auto 等待修正）；Ruff、Mypy（140 个源文件）、派生文档检查、118 份 Markdown 的链接/导航检查通过。离线构建 sdist/wheel 成功，wheel 独立导入及六个独立型号逐一移除检查通过。
- 实机发现 Socket 多行选件表会污染下一查询，已补发送前拒绝与能力不可读回归；仅表头也不能通过选件解析。通用规则补充“行结束不等于回复结束”和“恢复记录按阶段隔离”。Socket 未获得优先资格；原设置在用户另行授权的新恢复批次中逐项核对，并通过三次 VXI-11 重连。失败与后续恢复均独立留档，没有覆盖失败记录。

## Auto 后等待稳定

按用户追加偏好，配置变化不再按三帧判为故障。从首个变化帧起等待最多 30 秒，后续无效帧不延长期限；有效帧恢复正常监测。期限到达后保持连接，只用中性文字提示暂停读取。在途查询正常收尾，迟到帧不显示、不保存；真实通信与解析错误仍停止。单次采集不自动重试。

33 项监测、保存及 Qt 定向回归通过，覆盖连续五次变化后恢复、到期无错误暂停、迟到帧零保存、真实通信异常，以及草稿和焦点保护。隔离 Mock 渲染的[等待中](../../design/reviews/acquisition-performance/auto-wait-1280x760.png)和[到期提示](../../design/reviews/acquisition-performance/auto-wait-expired-1280x760.png)均已检查，没有红色故障状态。此次等待策略修正未再次操作真实仪器，前述实机数据与恢复批次保持原证据边界。

软件测试不证明物理精度或实机吞吐量。实机性能入口及停止/恢复规则见[型号硬件说明](../../src/lab_control/instruments/devices/rigol_dsa815/hardware/README.md)，公共维护要求见[采集规则](../architecture/live-acquisition.md)。

## 后续查询事务优化

上述 1191 项及 45/23 次统计保留为前一阶段基线。后续实现将公共流的首字节读取改为有明确 read-up-to 语义的整块预取，增量查找文本终止符，原生 TCP/VICP 关闭 Nagle。新增公共标量查询拼接/回复字段校验，由型号显式选择，不能自动推广至其他设备。

DSA815 经只读验证的固件/VXI-11 组合保留 full/live 的原字段集合和前后比较，使用参数组、轨迹、参数组三次事务；缺失/多余字段、无效值、配置变化、截断与超时均停止当前帧，不逐条重发。事务优化对照批次保持当时的 5 秒完整刷新，以隔离变量；后续按用户偏好改为 30 秒，首帧/失效/完整保存立即核验。Auto 等待和会话串行约束不变。诊断同时显示事务与 SCPI 子查询数。

协议试验的换行终止路径没有测得改善，因此未采用；其临时验证脚本在重连调用处出错，未发送设置写入，已作为该批次的软件执行失败保留。复合查询试验完成 20 帧对照、参数未变检查及三次重连；生产入口的最终复核记录以正式运行目录为准。此前 Socket 恢复失败及未获优先资格的结论不变。

## 低频、暂停与错峰复核

用户追加要求已落到公共同步服务，覆盖所有型号：空闲时前台/后台 30/60 秒；监测/记录期间拒绝独立静默读取；自动参数批次全局至少相隔 50 ms，首次读取和长任务结束后恢复同样错峰，不补发遗漏的批次。用户设置和主动读取不受该间隔限制。仍保留并发上限、设备间轮转和原始读回时间。电源通道标题继续显示同步质量，输出旁去掉重复状态，避免错峰首次读取时的临时文字撑宽卡片。

增加跨信号源、电源和频谱仪的低频/刷新回归、监测帧间零独立查询、六设备启动错峰与十分钟暂停后无补发，以及 30 秒完整上下文边界。既有二十设备并发回归仍核对慢设备、错误设备、监测测量读取与用户写入互不混淆。

最终全项目 **1245 通过、1 跳过**（166.76 秒）；Ruff、Mypy（141 个源文件）、生成一致性及 118 份 Markdown 检查通过。使用项目 Python、uv 缓存离线构建 sdist/wheel，通过 wheel 独立导入和六个型号逐一移除检查。隔离 Qt 真实页面渲染和一次完整保存通过：[1280×760](../../design/reviews/acquisition-performance/query-priority/monitor-1280x760.png)、[1440×900](../../design/reviews/acquisition-performance/query-priority/monitor-1440x900.png)、[元数据](../../design/reviews/acquisition-performance/query-priority/render.json)。截图耗时来自 Mock，不作为硬件速度证据。

生产查询策略按原格式只读比较四组各 20 帧，随后 60 秒监测和三次重连通过；追加最新 30 秒上下文及同步启用条件下的 65 秒监测，独立参数读取为零，原参数及额外状态逐项核验一致。未修改网络、扫描或仪器参数，未自动保存完整曲线。软件测试覆盖其他格式、零跨度、配置变化、超时和错误；此次只读实机复核不代表重新完成这些控制分组或物理精度验收。真实身份、资源、分布统计、通信与失败历史只保存在运行目录。

## 无轮询监测、记录锁定与二进制默认

用户确认监测与连续采集中不穿插参数查询：DSA815 首帧或失效后完整核对，稳定帧仅查询一次轨迹，无周期到期刷新。软件参数修改、Auto、主动“刷新参数”、异常、重连或新运行编号重建快照；未轮询的前面板修改须用户主动刷新。纯监测可编辑，连续采集/记录才锁定参数和 Auto，草稿不丢失。软件标记及本地间隔仍可调整。记录中的手动保存和定时保存使用同次快照，缓存来源/时间不完整时拒绝保存；未记录时手动保存仍使用完整新帧。

公共调度允许已具备完整快照来源的记录帧在读取期间等待前一写盘结束，回包时若写盘仍忙则丢弃本次保存机会，不排队；避免快写盘造成隔帧漏存。其他未声明 stream 的型号沿用原路径。跨层测试覆盖零设置写入拒绝、锁定收尾、新批次、主动刷新和监测草稿、慢写盘、超时及来源校验。

用户提供 REAL32 示例后进行了独立 ASCII/REAL32 实机比较，并确认连接 DSA815 默认二进制。公共连接层新增可选型号初始化入口，在身份及占用核验后执行；DSA815 读取原格式/字节序，必要时设置 REAL32 并核对结果，已有二进制零设置写入。失败无重发/回退，扫描不初始化；只读预检、备份和恢复显式跳过。后续型号优先采用经过厂商依据和正确性验证的二进制，不照搬命令或字节序。

全项目 **1279 通过、1 跳过**（172.66 秒），随后软件标记保持可用的 UI 补检 **11 通过**；Ruff、Mypy（141 个源文件）、生成一致性、118 份 Markdown 链接/导航检查、离线 sdist/wheel 及六个型号独立导入/移除通过。隔离 Qt 检查监测与记录在 1280×760、1440×900 的排版、按钮状态和保存流程：[监测](../../design/reviews/acquisition-performance/stream-binary/monitor-1280x760.png)、[记录](../../design/reviews/acquisition-performance/stream-binary/recording-1440x900.png)、[渲染元数据](../../design/reviews/acquisition-performance/stream-binary/render.json)。图中时间来自 Mock，不作为实机速度证据。

实机格式对比四组各 20 帧通过；默认二进制连接、65 秒记录、35 秒纯监测、三次重连及参数恢复通过。稳定帧单查询、无独立参数轮询，记录提交与收到的有效帧数一致；此处记录器只写元数据，完整文件保存使用 Mock。物理精度及新扫描率未验收。早期测试脚本误使用会导出文件且返回路径的连续采集入口，生成 21 组完整曲线后在返回值检查处失败；仅清理了经身份/时间/通信哈希核对的本批次文件，保留失败与清理清单，后续测试在采集之前安装元数据导出器。未修改扫描或网络，格式在测试结束恢复，软件下次正式连接按默认二进制重新设置。全部实机证据及真实标识仅在运行目录。

## 采集、显示与保存流水线

新增最快采集和自定义 0.5～60 秒间隔，新设备默认最快、已有数值偏好保留为自定义。读取完成主动唤醒调度，仍只有单设备一个查询在途，用户控制不会被连续读取饿死。发布不可变帧，Qt 合并新帧通知，仅可见页面绘图；不再随新帧重建坐标标题和不变的对数设置。参数列表与曲线更新分离，草稿和输入焦点保持。

连续记录从同步逐帧 JSON/CSV/NPZ 改为有界二进制写入，CSV 子进程定期增量转换；手动单帧和历史导出保持原格式。缓冲满显式暂停记录，二进制排空后释放参数锁，CSV 收尾不占用仪器。覆盖停止后重新监测、CSV 尚未完成时的停止等待者、磁盘/文件收尾错误、检查点前中断、半帧尾部与恢复后零重复行。全局最多两个 CSV 进程；每次记录只有一个转换在途。

相同 Mock/Qt 图形组件下，对照旧 100 ms 轮询与新帧通知，各预热 1 秒、测量 3 秒：有效帧均收到 73 帧，显示 27/72 帧，收到到绘图中位延迟 21.25/3.31 ms，P95 为 41.10/6.04 ms。基线显示也只取最新帧，故延迟中位数不等于 50 ms；该对照只证明本机软件通知收益，不代表硬件扫描率。[完整对照](../../design/reviews/acquisition-performance/pipeline/display-comparison.json)。初始 QTest 长等待方式影响 Python 工作线程调度，未预热的小样本结果另存[初始测量](../../design/reviews/acquisition-performance/pipeline/display-initial-harness.json)，不用于改善结论；最终驱动使用 processEvents 与释放 GIL 的短 Python 等待。

实机比较保持 REAL32/SWAP 和原扫描配置，对 VXI-11、VISA SOCKET、原生 TCP 各进行 20 帧完整/缓存读取；VXI-11 成组读取另作生产基线，TCP_NODELAY 单独比较。完成 65 秒记录、三次重连与逐项恢复，未生成曲线文件。两个 Socket 候选独立身份确认及被动读取通过，但完整选件表备份/全部传输资格仍受阻，因此不修改默认协议或资格记录。初次批次因测试计数边界误将停止后的后台读取计入断言而失败，恢复通过并保留；修正边界后的新批次通过。真实标识、耗时分布及两批结果仅保存在运行目录。

全项目回归 **1299 通过、1 跳过**（190.39 秒）；随后停止等待者、CSV 收尾锁、内存预留、文件关闭失败及最终绘图改动的定向复核 **34 通过**。Ruff、Mypy（143 源文件）、派生文档一致性及 118 份 Markdown 链接/导航检查通过。项目环境离线构建 sdist/wheel，并完成 wheel 独立导入及六个型号逐一移除检查。多设备回归使用独立保存间隔，缓冲满暂停由专用慢磁盘测试验收，不再假定有限磁盘可无限接收最快 Mock 的每帧文件。
