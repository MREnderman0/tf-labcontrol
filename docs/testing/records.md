# 实机测试记录规范

本规范适用于所有设备及后续新增型号。**每次真实测试都要留记录，无论通过、失败或受阻。**

## 存放与索引

默认根目录为 `%LOCALAPPDATA%\TF-LabControl\hardware-tests`，若设置 `LAB_CONTROL_HOME`，则使用该目录下的 `hardware-tests`。

按 `<完整型号>-<序列号>/<日期时间>-<测试类型>/` 分批保存，不覆盖旧结果。已有当天唯一批次目录可继续追加不同阶段文件。没有可信序列号时分配人工资产号并注明身份可信度，不能把地址当成序列号。

每批至少保存 `record.md`（结论和操作说明）与 `results.json`（结构化结果、原始读回和时间）。可附加 `readonly.json`、通信日志、截图或波形数据。完成或受阻后通过公共文档维护器更新根目录 `index.md`，按批次去重为表格；使用独立文档锁，取得锁后重新读取摘要，保留其他任务条目，不直接追加文字。

新批次同时保存派生 `summary.json`，不改变原始 `results.json` 的型号细节。统一摘要不参与设备控制或恢复判断；原始证据始终优先。

派生摘要写入失败时记录诊断及可写入的 `summary-error.json`，不得因此打断设备恢复。离线导入可以从原始结果重新生成摘要；补做成功后移除该派生错误文件。

真实身份、地址、配置和测量原始数据留在运行目录；源码只提交规范、脱敏示例和测试夹具。

所有设备的资产目录均维护 `connection-status.md`，固定为“当前结论、接口验证矩阵、功能覆盖表、已知问题、批次索引”。补测更新对应表格，不在文末新增流水式结论；模板见[资产测试状态](templates/asset-status.md)。USB、LAN 等接口分别记录时间、条件及证据，功能行按设备类别扩展。

物理链路亮灯不能标为通信通过；现场 LAN 失败不能写成型号不支持 LAN。关联历史排查和恢复批次，后续通过不覆盖先前失败记录。涉及编辑存储器等二进制状态时，必须保存完整备份和哈希，并记录最终逐字节/哈希核验结果。

## 必填内容

- 测试日期、操作者/任务、项目版本或未提交修改说明、Python/PyVISA/厂商驱动版本。
- 厂家、完整型号、序列号、固件、资源地址、连接方式、负载和允许的测试范围。
- 初始状态：输出、波形、频率、电平/幅度、偏置、负载、影响测试的耦合和工作模式。
- 每项操作：通道、请求值、实际读回、预期、结果、时间及错误。保留原始身份响应和必要的通信记录。
- 恢复：逐项比较原值和最终值；明确最终输出状态、未恢复项和恢复失败原因。
- 关闭/重连结果、尚未测试的功能、下一步动作。

## 结果分级

每项使用 `passed`、`failed`、`blocked` 或 `not_tested`，并附证据或原因：

| 阶段 | 通过依据 |
| --- | --- |
| 系统枚举 | USB/网络设备或 VISA 资源被发现 |
| 身份识别 | 真实身份响应与目标型号、序列号一致 |
| 兼容层连接 | 通过项目适配器、会话与身份校验完成连接 |
| 参数控制 | 明确参数经过兼容层写入并读回一致，核实通道隔离 |
| 恢复 | 修改项恢复并核对最终输出状态 |
| 重连 | 释放会话后重新打开、身份和读回正常 |
| 物理输出 | 外部测量仪器核对波形/频谱/电压等实际结果 |

未测试物理输出时，结论只能是相应通信或参数控制通过，不能写“设备全部正常”或“完整验收通过”。软件 Mock 测试与实机结果分开列出。

## 执行顺序

1. 确认目标和资源占用，保存初始状态。

   从打包桌面环境或其他启动环境执行时，运行时会先解析库存文件的最终物理父目录，并让库存、配置、硬件记录和全局锁共用这个根目录。文件系统重定向可能使相同文本路径指向同一份物理文件；记录中同时保留逻辑路径和最终路径，不能把另一份库存或锁当成正式运行环境。若路径无法统一，才改用与正式程序一致的执行环境再验证，不覆盖另一份库存。

   同一正式运行时内可以调度不同资产；不同真实 GUI、CLI 或 Python 进程通过固定位置的独占 `hardware.lock` 互斥，不能同时启动实机任务。会话还在 `devices/` 中独占资源、LAN 主机和型号/序列号对应的锁；连接前要求明确型号及预期序列号，识别后再核对真实身份。不同接口或地址指向同一资产也不得同时控制。未知身份探测受排他别名锁约束，活动会话期间推迟探测；广播枚举不发送参数命令。锁被占用时等待持有进程正常结束，不终止、不删除锁、不换目录绕过。操作系统在进程退出时释放锁，保留锁文件本身不表示占用。实现边界见[系统架构](../architecture/system-architecture.md#运行入口)。
2. 执行已授权的测试范围；信号源的参数控制验证默认保持输出关闭，其他类别按本次明确计划执行。
3. 参数修改异常时停止后续测试，不自动重放不确定的写入；先读取实际状态，再恢复。
4. 核实恢复与输出状态，释放会话，按计划重连。
5. 写入结果文件与台账，在交付说明中给出记录路径；受阻也完成已做工作的留档。

## 版本化摘要与型号职责

摘要版本为 `schema_version=1`，包含 adapter_id、model、真实 identity/身份可信度、预期序列号、resource/interface、起止时间、scope、environment、source_version、items、final_state、diagnostics、completeness/issues 和原始 evidence 文件哈希。

items 每项保留统一 key、原始 source_key、status、raw_result 和原因；合法状态仅为 passed、failed、blocked、not_tested。原字段为其他枚举时保留原值并列为待核对，不推断通过。缺少身份、固件、时间、范围或版本不填造数据，completeness 标记 needs_review。

公共记录模块只处理摘要、校验、哈希及文件。每个型号的 `hardware/records.py` 提供 `recognizes(report, folder)`、`summarize(report)`、`publish_report(folder)`；目录名只用于选择转换器，不能证明资产身份。未知或已移除型号仍保留原文索引，禁止借记录导入打开通信资源。

## 离线检查与总览

明确传入实际 `hardware-tests` 目录，工具不读取库存、不加载 VISA 运行库、不连接设备。执行前核对打印的最终路径；Windows 打包桌面环境可能显示合并的 AppData 视图，需要在与正式程序一致的原生环境运行，并显式列出旧重定向目录作为额外来源。

```powershell
.venv-dev\Scripts\python.exe scripts/hardware_records.py import --root '<正式运行目录>/hardware-tests'
.venv-dev\Scripts\python.exe scripts/hardware_records.py check --root '<正式运行目录>/hardware-tests'
.venv-dev\Scripts\python.exe scripts/hardware_records.py index --root '<正式运行目录>/hardware-tests'
.venv-dev\Scripts\python.exe scripts/hardware_records.py structure --root '<正式运行目录>/hardware-tests' --source-root '<旧运行目录>/hardware-tests'
```

历史来自多个目录时，import 可重复传入 `--source-root '<旧运行目录>/hardware-tests'`。只向目标根目录的 `overview/` 写入派生文件，额外来源保持只读。每次 import 指定完整来源集；index 使用上次导入清单，不扫描其他位置。

- `overview/README.md`：按可信资产、接口、项目、固件分组，列最近已执行结果和全部批次。
- `overview/needs-review.md`：缺项、未知格式、空批次和损坏记录，不静默跳过。
- `overview/summaries/`：带来源路径和哈希的摘要；manifest.json 保存本轮来源清单。

只读批次不覆盖此前控制证据；not_tested 不代替之前的已执行结果。后续恢复成功保留原始失败批次。不同固件、接口和测试条件不能合并成“整机通过”。LAN 内的 VXI-11、HiSLIP 和 VISA SOCKET 分开汇总，并在条件列显示协议；Socket 只读通过不覆盖 VXI-11 受阻，也不直接取得另一协议的参数控制资格。汇总只是历史证据，不代表当前在线或当前输出状态。

`import/index/check` 不修改人工连接说明、默认配置及原始证据。显式 `structure` 会整理正式根目录的 `index.md` 和各资产 `connection-status.md`，首次替换前将原说明按哈希完整保存在同目录，保持其相对链接；额外来源始终只读。默认连接读取运行目录的 `connection-preferences.json`（身份核验后的库存选择记录），缺失时标未核对，不从最近一次测试接口猜测。

所有型号的硬件入口在批次完成后调用公共 `refresh_after_batch`，只整理派生摘要，不读取库存、不加载 VISA。公共维护器不解析型号协议；摘要缺项列待核对。文档失败写入本批 `documents-error.json`，不打断设备恢复。原始结果、通信、快照、配置及备份不被结构整理修改。重复执行应得到相同内容；check 检测证据文件变化。人工确认的补充结论另建批次，不修改旧失败记录。
