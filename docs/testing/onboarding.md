# 新设备接入流程

本流程适用于后续新增设备，不以现有四台信号源的测试矩阵代替其他类别的要求。

## 1. 建立资产和资料

记录完整型号、厂家、可信序列号、固件、接口/选件、驱动和现有输出状态。型号不完整时只建立待补条目，不能猜测协议。实际身份、地址、图片和手册下载存放运行目录；型号包保存官方资料出处、版本、章节及脱敏样本。

同型号不同序列号是不同资产；同一资产的 USB/LAN 等接口分别验证。地址可变，不能用 IP 当永久资产身份。无可靠序列号时保持人工资产号和待核对状态。

## 2. 实现独立型号包

按[模块规范](../architecture/device-modules.md)建立包、注册项、README、tests 和 hardware。使用[模板](templates/README.md)填写支持范围、单位、组合约束、查询失败行为和恢复边界。公共层只保留通用兼容机制，不加入本型号的命令、范围或历史格式分支。

同时按[部署规范](../development/desktop-deployment.md)登记运行依赖、驱动/SDK、服务和网络要求，在型号元数据 `deployment_components` 引用组件 ID。记录官方来源、版本、安装材料哈希/签名、分发依据、检测/安装与恢复方法；未知项标待补。完成组件登记检查及实际打包回归，不能把依赖下载工作留给最终用户。

通过型号工厂和项目会话验证软件行为，覆盖错误响应、越界、通道隔离、超时不重发、恢复失败。完成导入、模块移除及文档检查；软件通过不自动提升实机状态。

接入自动设置、自动量程或轨迹采集时，遵循[监测一致性与调度规则](../architecture/live-acquisition.md)：验证设置完成后的暂态、前后配置变化、无效帧不保存，以及慢读取/写盘下独立刷新与保存间隔。不能把设置确认直接当成曲线有效，也不能用放宽容差掩盖变化。

## 3. 明确本次硬件测试范围

先准备可评审的测试计划：精确资产与接口、目标操作、负载/接线、备份清单、预期读回、比较容差、停止条件、恢复顺序、未测项目。写入或输出操作必须在已有授权范围内；通用文档不自动授权输出或采集启动。

核对正式运行目录、配置、库存及全局锁的最终物理位置。桌面打包环境可能让 AppData 的逻辑路径与物理路径不同，程序会统一使用库存文件解析出的物理运行根目录；不能以另一副本的空闲锁替代正式锁。

## 4. 执行与留档

先只读身份核验，再按计划备份与测试。每次成功、失败、受阻及中止都保存独立批次。异常停止后续测试写入，读取实际状态并执行有依据的恢复；最终状态无法确认时明确写未知。

按[记录规范](records.md)保存原始结果、通信、快照、备份/哈希和 summary.json。关闭/重连、控制及物理测量分别判定，不把设置读回当作物理输出精度。

## 5. 交付与后续补测

运行离线台账导入及检查，将实际接口、测试范围、恢复、未测/受阻和下一步写入资产说明。型号 README 只维护脱敏结论及限制；具体资产、地址与证据链接在运行目录。

补测另建批次，保留旧失败和恢复过程。所有类别采用[资产状态模板](templates/asset-status.md)，直接更新对应表格；不在现行文档末尾逐次追加测试段落。型号 README 按能力/协议、连接/驱动、范围/约束、测试入口/验证范围、已知限制/待测及扩展方式维护；只保留脱敏结论。硬件入口生成最终摘要后调用公共 `refresh_after_batch`，不自行追加索引或覆盖人工说明。移除型号不删除用户配置、资产历史和实机记录。
