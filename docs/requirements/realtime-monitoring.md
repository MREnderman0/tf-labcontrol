# 实时监测设计与实现（0.3.0）

本文件是实时监测页面、布局和任务行为的当前依据；操作步骤见[控制与监测指南](../guides/control-and-monitoring.md)。本轮没有阈值告警、自由拖拽/缩放、自动实验编排或历史数据处理工作台。

## 页面分工

实时监测的子页以总览为固定入口，其余设备类别标签只在该类别存在已连接会话时显示；类别最后一台设备断开后自动回到总览。总览显示所有已连接且存在数据源的设备，每台设备一张卡片，按设备类别分组，包含光功率计。卡片显示完整设备身份和功能槽位，仅提供采样间隔与“参与采样”复选框；勾选状态按设备适用模式和槽位保存，槽位更换设备后沿用上次选择。右上角“一键开始采样”只为勾选设备创建记录任务，未勾选设备不会发起请求；任务运行时同一按钮停止采样。断开会话的设备立即从总览移除。其余设备类别页共用设备选择器，显示 A/B 槽位、型号、资源、连接状态和通道。

信号源的写入参数在设备管理，监测页展示设置读回，不伪装成输出波形。电源、示波器、频谱、光功率、万用表、网络/相噪的工作参数放在监测页右侧。电源采用上下电压／电流趋势与紧凑通道卡片，每周期共用一个标量采集；旧控制路由转入实时监测，设备池不重复提供控制入口。温控/负载/泵浦/光谱未知型号仅有隔离 Mock 演示，不能向真实未知设备写入。

光功率计是监测专属页面：设备管理仍显示“光学测量”分类卡片和连接流程，但不显示光功率计控制子页，旧入口直接跳转到“实时监测 → 光功率计”。页面一次展示能力快照中的全部通道，复选框同时控制曲线、读数卡片和采集请求；首次使用全选，之后按功能槽位持久化。采集中切换通道会使当前请求结果失效并刷新请求集合，监测任务保持运行；取消全部时只暂停采集，重新勾选后恢复。每个有效帧追加一个点，趋势最多保留 1200 点且不超过 600 秒。“开始监测”只启动显示采集，“开始记录”才逐帧保存，停止时等待二进制收尾。主显示统一为 W：W 原值直接显示，dBm 只在显示层按 `10 ** ((dBm - 30) / 10)` 换算；原始批次、单位和导出文件保持设备返回值。右侧常驻小卡片只展示整机波长，功率读数由通道卡片负责，卡片固定紧凑尺寸，数值显示 6 位有效数字，完整值可悬停查看。

参数控件来自 CapabilitySet，中文标签在 application/controls.py。未注册的功能没有执行按钮，缺选件项显示原因并禁用。普通监测的单次读取、开始/停止监测、保存当前数据和开始/停止记录是独立动作；仪器运行/停止/触发仍是单独的能力操作。相噪仪使用下述有限任务，开始采集同时授权测量与保存。

## 总览卡片与布局

卡片由当前已连接且存在数据源的设备自动生成，每台设备只有一张。设备按类别分组，卡片显示厂家、型号、序列号和当前模式的功能槽位；断开会话后从总览移除。槽位只用于确认和保存选择，不把 COM/IP 当物理身份。点击设备名称进入对应类型页。

列数按 `max(1, floor((内容宽度 + 16) / (360 + 16)))` 计算。360 为目标最小宽度，16 为间距，单位均为逻辑像素；窄窗口单列，同行等宽，超出高度纵向滚动。没有列数选择器、默认两列或最多三列规则。窗口和侧栏宽度变化只移动现有卡片对象，保留顺序、图形、选择与任务。

总览统一保存卡片的采样间隔和参与采样状态，不保存列数。参与采样状态以设备适用模式和功能槽位为键，槽位更换设备后沿用；无槽位设备使用稳定设备 ID。进入总览不会自动启动采样，右上角统一开始或停止勾选设备的记录任务。切换设备或页面后，各监测页从 `MonitoringService.latest()` 恢复最后一帧有效图形或读数，不重新访问仪器。

## 数据显示

| 数据源 | 显示与约束 |
| --- | --- |
| 示波器 | 多通道时域波形；Pico 可选有限 streaming 批次 |
| 频谱仪 | 频率轨迹；零跨度采用设备返回的秒轴 |
| 光功率/万用表/电源 | 当前读数与有界趋势；保留单位和质量 |
| 网络分析仪 | 当前复数 S 参数的幅度 dB / 相位 °，共享一次采集 |
| 相噪仪 | 定时相位采集、相噪、重叠 ADEV/MDEV；高级 AM 与旧数据流接口暂不加入专属页面 |
| 信号源 | 频率、幅度或功率、输出的设置读回，不是实测波形 |

PyQtGraph 使用软件绘制与 peak 抽稀；导出保存未抽稀原始数据。每个标量显示序列最多保留 1200 点且不超过 600 秒；后台按设备/数据源只保留最近一批。示波器／频谱仪启动使用自定义 0.5 秒，可选最快或 0.5～60 秒；电源启动使用 1 秒，只提供 1、5、10、60 秒四档。本次运行的选择按设备／工作模式共享，间隔表示目标请求开始间隔，不代表固定采样时间。不同数据源请求轮转，以请求开始时刻计算间隔；慢读取结束后不再额外等待完整间隔，也不补发积压请求。页面显示实际有效帧接收间隔；这不是仪器采样率，也不保证实时硬件同步。

图上显示主机 UTC 更新时间、测量单位、数据质量、配置版本和任务状态。暂停或失败保留最后有效画面及原因；没有数据不会补零。不同配置版本的旧帧不能覆盖新结果。无间隙无限流、多 S 参数自动轮换、数学波形和完整分段采集未开放。

## 相噪仪定时采集

正式“实时监测 → 相噪仪”页面集中提供采样率、采集时长、输入/参考自动或手动频率、开始/停止、进度及数据目录。上方显示相噪，下方显示 ADEV/MDEV；到时或提前停止后保留有效结果。旧设备管理入口转入同一页面，切页和连接不会自动开始。

53100A 托管 USB 连接开放 1、10、100、1000 samples/s，时长 10～86400 秒且总相位点数不超过 4,000,000。时长从首个有效相位样本计算；采样率决定相位流与最小 τ，不等于界面刷新率或相噪频谱上限。参数在采集及二进制收尾期间锁定，正常使用保留所选设置。具体协议、点数约束与算法以[型号说明](../../src/lab_control/instruments/devices/microchip_53100a/README.md)为准。

此任务不使用普通监测的轮询间隔；一次启动持续读取，逐段校验并自动保存，停止还须核对仪器状态。提前停止标为部分时段，通信或连续性错误立即中止且不重放写入，停止未确认时显示最终状态未知。原始相位与统计量进入公共有界流水线；相噪沿用各次实际查询时间，不能把缓存频谱算作新的采样结果。当前软件及模拟回归通过，带 DUT/参考信号的实机采集和物理性能仍未测试。

## 调度与控制

MonitoringService 调度原 SessionManager worker，每台设备只有一个通信执行队列。相同 kind/quantity 合并通道后分发到各卡片；新请求的点数/采集选项替换相同数据源的旧选项，不创建第二会话。不同请求在该 worker 顺序执行。

应用参数先完成当前读取，再执行整组设置/读回和错误检查，增加配置版本，然后继续下一批。参数拒绝、部分执行、不确定或通信错误暂停目标设备；其他设备继续。没有自动重发、回滚或恢复输出。

完整有效回包中的配置变化属于无效帧，不等同连接中断；丢弃且不保存，后续轮询有界等待稳定。具体分类、最长 30 秒等待及单次读取约束见[监测一致性与调度规则](../architecture/live-acquisition.md)。电源、示波器和频谱仪设备池只保留一个“实时监测”入口，旧设备管理路由继续转入同一页面。

普通监测停止时只停止软件读取；当前 I/O 返回后完成停止，不发送仪器输出关闭。有限测量按型号的停止流程收尾。运行期间禁止断开、重连、换槽。切页和扫描不停止任务，扫描只用活动会话缓存。记录或控制进行中禁止切换模式；停止记录还会等待已授权的在途批次和写盘结束。

## 记录与保存

示波器和频谱仪每次软件启动恢复自定义 0.5 秒间隔，本次运行内的修改按设备及工作模式共享；不因重新进入页面或 Auto 重置。纯监测不创建实验数据文件，只有布局、草稿与审计持久化。公共控件统一普通监测节奏：电源为 1、5、10、60 秒（启动恢复 1 秒），其他轮询页面为最快或 0.5～60 秒自定义间隔；开始记录后逐帧保存，无独立保存间隔。二进制写入与采集并行，有界缓冲最多 64 帧或 128 MiB，满时明确暂停记录并排空；不静默漏存。CSV 后台固定每 5 秒转换，停止后补齐。用户停止记录前已经提交的记录读取仍完成保存。手动“保存当前帧”导出图上实际显示的完整数据及原配置来源，不重新访问仪器；慢写盘不阻塞监测和调参。

新记录路径来自软件设置的“数据保存一级目录”，默认运行目录下的 `data`，按单设备采集、本地日期、毫秒开始时间与设备身份分层；类型为 `continuous` 或 `single_frame`，模式保存在元数据中。开始时固定路径，跨午夜、排队写盘及更改设置不改变正在保存的目录；准备失败撤销记录状态及参数锁。真实与模拟的设置及数据保持隔离，旧目录保留，批量路径接口预留而不新增操作界面。详见[数据模型](../data/data-model.md)。CSV/NPZ/JSON 保留原始帧时间、通道、数值、坐标、单位和质量。SDK 无硬件读回的设置明确来自本会话缓存；未知保持未知。
