# 操作日志与系统设置需求

## 操作日志

当前“操作日志”只有一个同名页签，页面说明按日保存的运行目录 `logs`；尚未提供日志列表、筛选或告警工作台。已实现的 JSONL 审计及失败证据边界见[数据模型](../data/data-model.md)。

后续日志工作台规划“全部日志、设备操作、采集与处理、异常与告警”子菜单。日志至少包含时间、工作区标签、设备、槽位或任务、操作、结果和错误原因；这些规划不代表当前 GUI 已提供对应入口。

审计目标包括扫描、连接、断开、重连、绑定、换槽、预设加载、参数应用、输出启停、采集、处理、导出、超时、断连、识别失败、数据质量异常和阈值告警。尚未交付的数据处理、阈值告警等流程需在实现时补齐对应事件；高风险批量操作需记录确认结果和逐台结果。

## 系统设置

当前系统设置只有“软件设置”一个页签，包含数据保存目录、软件库存与日志目录说明，以及“环境与修复”。环境面板提供后台检查、取消并保留部分结果、修复方案、JSON 报告导出和明确选择后的材料准备；厂商安装向导由用户点击打开，自动网络修改仍待实现。具体状态、离线材料和执行/恢复要求见[部署与环境修复](../development/desktop-deployment.md)。检查完成不得显示为修复成功。

独立的“数据存储、通信设置、日志设置”子菜单、实验保存策略编辑、通信默认值及日志级别/保留策略编辑尚未交付。当前主题固定为已确认的深色琥珀分类卡片样式；扫描、连接与重连仍从设备管理入口操作，不能把旧设置页设想当成现行功能。

当前统一使用 general 通用工作区，设置与侧栏不提供电子学／光学模式选择或标识。设备操作仍检查能力、连接、范围、任务锁及必要确认；不会因工作区初始化自动连接、开启输出或恢复设置。
