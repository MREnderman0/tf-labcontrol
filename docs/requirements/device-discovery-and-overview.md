# 设备发现与总览设计（0.3.0）

本文是扫描、身份识别、会话保护、库存合并和设备总览行为的唯一设计入口。已接通真实 ApplicationRuntime；lab-control-demo 保留独立演示。

## 服务边界

DiscoveryProvider 只负责 enumerate() 返回 DiscoveryCandidate；DiscoveryService.scan() 返回 Future[ScanRun 字典]，cancel() 取消后续探测；SessionManager 提供 snapshots()、connect()、submit()、start_acquisition()/stop_acquisition()、disconnect() 和 subscribe()。身份探测集中在 ApplicationRuntime.probe，避免 provider 持有控制会话。手工刷新通过 submit(device_id, "identify") 进入原 worker。

## 扫描顺序

    点击扫描
      -> 新 ScanRun，拒绝重复提交
      -> 并行枚举 VISA / COM / 已配置 SDK / 手工资源
      -> 规范化资源，全部候选先增量入库
      -> 对每项原子检查租约和当前会话
      -> 活动资源复用身份缓存；未知别名延后
      -> 已授权非活动资源短期探测并关闭自身句柄
      -> 注册表匹配、身份合并、逐项日志
      -> 仅完整成功覆盖的范围计算 stale，保存汇总

VISA 只枚举运行库已知资源。USB INSTR 对已知仪器厂商 VID 白名单执行有限 *IDN?，没有型号白名单的未知 COM/网络/GPIB 只保留描述；明确配置型号后才采用型号的身份查询。3458A 使用 ID?，不遍历 *IDN?/厂商命令。LAN 不做全网扫描。

SDK provider 仅执行厂商非侵入式枚举；按 SDK 路线隔离，某一 SDK 失败不取消 VISA/串口/其他 SDK。PM100D/Pico 身份须用户连接后由适配器读取；扫描不打开 SDK 仪器或启动 TSERVE。

## 不打断会话的硬性规则

- 连接、控制和采集中的设备只使用原会话缓存，不发送额外身份/状态查询。
- 空闲已连接设备的手工刷新也必须走原 worker，不能开第二句柄。
- 开探测句柄前在会话锁内原子取得资源/别名租约；连接同时检查探测门闩，防止检查快照后发生竞争。
- COM 与 ASRL、相同主机端口的 VISA Socket 与直接 TCP 统一；其他别名只接受已确认关系。
- 无法排除新资源指向活动设备时，记录 deferred_possible_alias_of_active_device 并延后。当前采取保守策略：有活动会话时未归属的新资源都延后身份探测。
- 扫描只关闭自身临时资源，绝不调用既有设备的 open/close/disconnect；应用级 VISA 管理器不会在扫描结束时关闭。
- 取消、超时、provider 失败保留已有库存。未发现不代表断开；连接状态只能由会话自身 I/O/恢复流程改变。

provider 枚举并行，身份探测目前串行以避免未确认 USB/LAN 别名碰撞。所有资源元数据先发布，单台慢设备不会阻止其他设备出现；后续身份结果可能等待该探测超时。取消不能强行中断正在执行的厂商驱动调用，后续探测停止。

## 状态和合并

发现状态与连接状态分开保存。库存使用持久 UUID，身份、原始资源候选、来源、配置、更新时间、错误和可信度详见[数据模型](../data/data-model.md)。

有可靠厂家/型号/序列号时合并多资源，保留原始候选与主/备用地址。空身份占位记录可以被已识别记录吸收；同资源身份变化或不一致信息进入 conflict，不覆盖原资产。冲突状态不会因后续只读枚举自动解除。没有序列号时不以 COM/IP 地址认定物理同一设备。

连接后才识别出与另一历史记录重复时，保留冲突，避免运行中替换 worker 的设备 ID；先断开并在下一次识别/人工盘点中处理。当前没有专门的资产冲突合并向导。

完整成功覆盖的来源才能令未出现资源 stale；取消、失败范围不能批量陈旧化。配置地址仅表明配置存在，不能据此认定设备在线。陈旧设备保留名称、槽位和历史身份。

## 总览页面

固定类别：信号源、电源、示波器、频谱仪、光学测量、万用表/网络/相噪、温控/负载/泵浦、未知。0 台也显示。

顶部显示扫描/取消、环境诊断、添加资源、最近扫描、已处理数与失败汇总。类别卡片显示发现/识别/连接/未连接/未知/异常/已绑定数量。页面内设备行按类别、识别/连接/适配器状态筛选。

详情展示厂家/型号/序列号/固件、可信度、发现状态、连接/任务、驱动、适配器、验收状态、主/备用资源、槽位、更新时间、跳过原因、最近状态读回与错误。原始候选和日志细节通过诊断查看；“查看能力”显示实际注册能力。

扫描不清空卡片、设备行或抽屉。以稳定设备 ID 更新，保留选择和滚动；仅合并被确认的重复占位行。总览每 300 ms 读取内存快照，不启动仪器采集或周期查询。

连接、断开、重连、刷新身份、读取状态、停止任务、名称、槽位、主资源均使用应用层。未知型号不提供危险控制入口。任务运行时锁定断开/重连/换槽；主资源仅在无会话时切换。当前忙时身份刷新按钮禁用，停止任务后重试，不强插查询。

## 模式与槽位

总览始终显示全部库存。模式切换只改变适用性与槽位候选：光功率计用于光学，频谱仪用于电子学，其余当前已知类别可用于两种模式；未知设备不可绑定。类别内提供两个初始逻辑槽位，应用层再次检查类别、模式、占用和任务状态。

不适用设备继续保留连接和状态，模式不更改物理输出。0.3.0 已接通[分类控制页](device-management.md)与[实时监测](realtime-monitoring.md)，当前类别槽位显示为 A/B。监测任务也保持原会话和租约，扫描始终复用缓存；批次间不能误断开或换槽。记录或控制进行中锁定模式切换，纯监测只改变视图与适用性。

## 日志和测试

日志记录扫描时间、provider 数量/失败、逐项身份/缓存/延后/错误、资源合并与会话操作。只有一个全局扫描任务，失败范围不覆盖其他结果。

自动化覆盖 20 台模拟会话保持、扫描/取消/连接竞争、未知串口不打开、别名租约、provider 失败、库存增量合并、UI 稳定行与模式切换。现场必须同时验证 VISA/COM/LAN/GPIB/SDK、扫描期间持续采集、插拔、双资源、驱动缺失、超时和占用；见[实机验收指南](../hardware-testing.md)。所有实机状态仍为待验证。
