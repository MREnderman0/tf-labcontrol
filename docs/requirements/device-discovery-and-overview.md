# 设备发现与总览设计（0.3.0）

本文是扫描、身份识别、会话保护、库存合并和设备总览行为的唯一设计入口。已接通真实 ApplicationRuntime；正式启动统一使用 run.bat，Mock 仅用于内部测试与预览，数据保持隔离。

## 服务边界

DiscoveryProvider 只负责 enumerate() 返回 DiscoveryCandidate；DiscoveryService.scan() 返回 Future[ScanRun 字典]，cancel() 取消后续探测；SessionManager 提供 snapshots()、connect()、submit()、start_acquisition()/stop_acquisition()、disconnect() 和 subscribe()。身份探测集中在 ApplicationRuntime.probe，避免 provider 持有控制会话。手工刷新通过 submit(device_id, "identify") 进入原 worker。

## 扫描顺序

    点击扫描
      -> 新 ScanRun，拒绝重复提交
      -> 并行枚举 VISA / COM / 已配置 SDK / 手工资源
      -> 规范化资源，全部候选先增量入库
      -> 对每项原子检查租约和当前会话
      -> 活动资源复用身份缓存；未知别名延后
      -> 已授权非活动资源短期探测并关闭自身句柄
      -> 注册表匹配、身份合并、逐项日志
      -> 仅完整成功覆盖的范围计算 stale，保存汇总

默认 VISA provider 只枚举运行库已知资源。USB INSTR 对已知仪器厂商 VID 白名单执行有限 *IDN?，没有授权范围的未知 COM/网络/GPIB 只保留描述；明确配置型号后才采用型号的身份查询。3458A 使用 ID?，不遍历 *IDN?/厂商命令。可选的 [LAN provider](../architecture/lan-discovery.md) 使用 VXI-11/mDNS 发现，并仅允许选定实验网卡/网段内的候选进行 *IDN? 核验；不逐地址扫描网段。启用后正式启动及手工扫描共用此路径。

SDK provider 仅执行厂商非侵入式枚举；按 SDK 路线隔离，某一 SDK 失败不取消 VISA/串口/其他 SDK。PM100D/Pico 身份须用户连接后由适配器读取；扫描不打开 SDK 仪器或启动 TSERVE。

## 不打断会话的硬性规则

- 连接、控制和采集中的设备只使用原会话缓存，不发送额外身份/状态查询。
- 空闲已连接设备的手工刷新也必须走原 worker，不能开第二句柄。
- 开探测句柄前在会话锁内原子取得资源/别名租约；连接同时检查探测门闩，防止检查快照后发生竞争。
- COM 与 ASRL、相同主机端口的 VISA Socket 与直接 TCP 统一；其他别名只接受已确认关系。
- 无法排除新资源指向活动设备时，记录 deferred_possible_alias_of_active_device 并延后。当前采取保守策略：有活动会话时未归属的新资源都延后身份探测。
- 扫描只关闭自身临时资源，绝不调用既有设备的 open/close/disconnect；应用级 VISA 管理器不会在扫描结束时关闭。
- 取消、超时、provider 失败保留已有库存。未发现不代表断开；连接状态只能由会话自身 I/O/恢复流程改变。

provider 枚举并行，身份探测使用有界线程池；资源、主机及未知别名租约共同防止未确认 USB/LAN 别名碰撞，不能将线程池并发等同于可对同一资产并发通信。所有资源元数据先发布，单台慢设备不会阻止其他设备出现；身份结果按完成情况增量发布。取消停止后续提交，不能强行中断正在执行的厂商驱动调用。

## 状态和合并

发现状态与连接状态分开保存。库存使用持久 UUID，身份、原始资源候选、来源、配置、更新时间、错误和可信度详见[数据模型](../data/data-model.md)。

有可靠厂家/型号/序列号时合并多资源，保留原始候选与主/备用地址。空身份占位记录可以被已识别记录吸收。授权的 LAN 身份核验确认旧 IP 已属于另一设备时，撤销旧地址归属，为新身份建立独立资产；旧资产、限制和记录保留，不转移给新设备。同一身份同时出现在不同 LAN 主机或其他身份不一致信息进入 conflict，不因枚举自动解除。没有可靠序列号时不自动合并，自动发现的 LAN 候选禁止控制。

连接后才识别出与另一历史记录重复时，保留冲突，避免运行中替换 worker 的设备 ID；先断开并在下一次识别/人工盘点中处理。当前没有专门的资产冲突合并向导。

完整成功覆盖的来源才能令未出现资源 stale；取消、失败范围不能批量陈旧化。配置地址仅表明配置存在，不能据此认定设备在线。陈旧设备保留名称、槽位和历史身份。

当前存在性单独使用 `presenceState`：present（本次发现）、not_seen（本次未发现）、unreachable（探测失败）、unknown（尚未确认）。启动时旧库存的存在性仅在内存中重置为 unknown；历史身份、名称、槽位和记录不删除。配置与枚举对同一地址的观察分别保存在候选的 sources 中，配置不能覆盖实际枚举来源，也不能单独刷新 lastSeenAt。

有效活动会话和成功身份探测可作为当前设备证据；尚未绑定型号的本地 USB/串口/SDK 枚举只作为待核对资源线索，放在全部设备中，不计入当前设备。对已有型号或身份记录，串口/USB 桥枚举只证明资源存在，不能单独证明该设备已发现；明确探测失败不以历史身份继续计算为当前设备。VISA 返回的未验证网络/GPIB 地址只作候选。多个已确认别名中仍有一个具备当前证据时，设备只计算一次。取消或来源失败使未确认的旧证据归入历史，不据此声明设备已拔出，也不改变会话。失效会话缓存不提升当前存在性。

## 总览页面

全部分类卡片统一按当前设备证据显示；没有当前设备的类别隐藏，历史库存不能单独产生卡片。全部为空时提示连接、开机并扫描；“设备列表”始终可打开设备池，按范围查看当前、历史与已配置或全部设备。设备池弹窗的类别筛选始终列出全部类别。

界面固定为[历史深色琥珀分类卡片版](../../direction-approved.md)。顶栏显示扫描，设备总览提供一键连接、取消扫描、环境诊断和添加资源。分类卡片显示可见数、在线数、未连接、异常和已绑定数量；点击后打开居中设备池，按类别、识别/连接/适配器状态筛选设备。首页没有整页设备表；摘要提示保留最近扫描及本次数量。

### 一键连接

一键连接固定点击时的当前设备集合，按稳定 ID 去重，不受设备池类别、范围筛选或工作模式影响。不同设备最多 4 台同时连接，每台沿用正式连接流程、已核验资源、型号初始化和进程占用锁；同一设备仍由独立会话 worker 串行操作。连接前检查、打开和读回均在后台执行，不持有界面进度与取消共用的发现锁等待设备。任一连接结束即补入下一台，慢设备不阻挡其他空闲名额。只连接设备，不启动输出、监测或记录；已有会话保持原状。未知型号、不可用适配器、身份冲突及已有连接任务/异常会话列明跳过原因；其他连接失败逐项记录后继续，不自动重试。

总览显示已完成数、进行中数、排队数和在途设备名称，结束后汇总成功、已连接、失败和跳过数量，“连接结果”按原设备顺序展示逐台原因。“停止连接”跳过剩余排队项，等待所有已提交连接结束，保留已成功连接的会话。批量连接与扫描由服务层互斥，界面同时禁用重复提交及连接、断开、重连、主资源切换。退出或协调器异常均先等待在途连接及身份保存完成，再释放批量互斥；退出随后关闭会话和仓储。

应用接口为 `ApplicationRuntime.connect_all_discovered()`（返回结果 Future）、`connection_progress()`（独立内存快照）和 `cancel_connect_all()`。连接审计逐项保存结果及最终汇总，软件连接成功不等同于实机验收通过。

详情展示厂家/型号/序列号/固件、可信度、发现状态、连接/任务、驱动、适配器、验收状态、主/备用资源、槽位、更新时间、跳过原因、最近状态读回与错误。原始候选和日志细节通过诊断查看；“查看能力”显示实际注册能力。

扫描不清空统计、设备行或弹窗。以稳定设备 ID 更新，保留选择和滚动；仅合并被确认的重复占位行。总览每 300 ms 读取内存快照，不启动仪器采集或周期查询。

设备池是总览页面内的居中弹窗，最大 960×640 逻辑像素，四周至少留 24 像素，背景覆盖半透明遮罩。常规宽度左侧为设备列表、右侧为设备身份、连接信息、功能槽位与发现记录；宽度不足 760 像素切换为上下布局，正文可纵向滚动。标题与常用操作固定可达，额外操作放入“更多”，记录任务单独显示停止操作。

切换页签、模块或程序内跳转即关闭弹窗，返回总览不自动重开；遮罩空白、关闭按钮和 Esc 均可关闭，露出的分类卡片可直接切换类别。遮罩不向底层按钮传递点击，下拉菜单与子对话框优先独立关闭。打开时焦点进入弹窗，关闭后返回触发入口；定时刷新、窗口缩放和扫描结束不重新打开。

设备池范围默认为“当前设备”，另可选择“历史与已配置”和“全部设备”，再叠加原有类别和状态筛选。摘要、分类卡片和类别数量统一使用当前证据与有效会话统计；历史记录不计入发现数量，在历史范围中标明本次未发现、探测失败或尚未确认。扫描开始保留已显示结果并增量更新，完成后按本次证据更新；当前选中项被筛选隐藏后清空详情，防止继续操作隐藏的设备。

连接、断开、重连、刷新身份、读取状态、停止任务、名称、槽位、主资源均使用应用层。未知型号不提供危险控制入口。任务运行时锁定断开/重连/换槽；主资源仅在无会话时切换。当前忙时身份刷新按钮禁用，停止任务后重试，不强插查询。

底部常用操作按“连接／断开、功能槽位、设备控制、实时监测、更多”排列，窄窗口可换行。连接保留实心强调，其余为统一深色描边。功能槽位不再放入“更多”；未连接时设备控制和实时监测入口禁用，提示先连接。分类控制和分类监测统一按会话筛选，不等同于总览的“当前发现”：仅枚举发现但未连接的设备仍只能在设备池内连接。

## 通用工作区与槽位

总览按设备范围筛选展示库存。全部已接入类别使用同一通用工作区，未知设备不可绑定。光功率计提供“功率计1、功率计2、功率计3”三个逻辑槽位，其他类别保留 A/B 两个槽位；应用层再次检查类别、工作区标识、占用和任务状态。原有光功率计槽位 ID 保持不变，已有绑定和按槽位保存的监测偏好继续沿用。

槽位按 general 通用工作区持久保存，仅用稳定设备 ID 或厂家、完整型号、序列号一致的可靠身份复用历史绑定；同型号其他设备不继承，首次出现且无历史绑定时保持未绑定。断开、重启或同一设备地址变化不清除绑定。明确解绑的空字符串与未记录该模式不同，身份合并遇到相互矛盾的人工选择时保留冲突，不能用历史值覆盖空绑定。

功能槽位选择器显示全部兼容槽位及当前占用设备。选择他人占用的槽位时，弹窗列出设备名称、型号、序列号和目标槽位，提供“替换”和“取消”，默认取消。确认后，新设备释放原槽位并取得目标槽位，原占用设备在通用工作区内保持空绑定；两台设备保持连接，旧历史模式数据不变。取消不修改任何绑定。绑定事务提交前重新检查占用者及双方任务状态；连接、控制、监测、记录和保存收尾期间拒绝换槽，弹窗期间占用变化须重新确认。

未注册设备保留库存和诊断入口，工作区不更改物理输出。0.3.0 已接通[分类控制页](device-management.md)与[实时监测](realtime-monitoring.md)，当前类别槽位显示为 A/B。监测任务也保持原会话和租约，扫描始终复用缓存；批次间不能误断开或换槽。记录、控制及收尾期间继续锁定相关参数和绑定操作。
