# RIGOL DHO924

注册标识 `rigol.dho924`；精确匹配 RIGOL TECHNOLOGIES DHO924、四个模拟通道。DHO924S、DHO914 和其他 DHO 型号不自动兼容。本目录是协议、范围与测试说明的维护源。

## 能力与协议

支持通道显示、垂直档位/偏移、耦合、探头倍率、时基/水平位置、存储长度、模拟边沿触发源/电平/边沿、AUTO/NORM/SINGLE/STOP；采样率是只读关联量。保留触发保持时间，不切换高级触发类型。

协议依据：[DHO800/DHO900 Programming Guide PGA39106-1110](https://download.rigol.com/en/Manual/Digital%20Oscilloscope/DHO800/DHO800900_ProgrammingGuide_EN.pdf)，3.3 采集、3.6 通道、3.12 完成同步、3.26 时基、3.27 触发、3.28 波形；型号时基规格参见 [DHO900 User Guide](https://download.rigol.com/en/Manual/Digital%20Oscilloscope/DHO900/DHO900_UserGuide_EN.pdf)。

WORD 用每帧自身的十字段 preamble 解析，数据契约为小端无符号 16 位；`V=(code-yorigin-yreference)*yincrement`，`t=(i-xreference)*xincrement+xorigin`。屏幕模式固定完整 1,000 点窗口；完整存储使用停止状态下的 RAW，拒绝超限或无法确认的窗口。ASCII 校验按实际返回的增益与样本十进制末位计算舍入界限，不用垂直档位作为容差。

显示元数据的可选垂直偏移方向为 −1、水平位置方向为 +1，公共界面据此即时预览档位/时基和两种偏移。仅变换上一帧的显示，不改实际数组；收到有效新配置帧后结束估算。

稳定监测/记录沿用公共 live/stream 上下文：每通道 SOURCE 选择（必要时）、PREamble 查询、WORD DATA 查询、PREamble 复核；首帧前后完整设置核验，后续保留原始设置时间。已知局部调参由 `control.py` 声明依赖，仅核验本通道/关联触发或水平采样存储组，保留无关缓存和时间；下一帧为 `cached`，仍按自身 PRE 解码并与新配置、DATA 后 PRE 比较。不追加整机能力查询或页面回读。主动刷新、Auto、未知依赖、重连、通道/批次变化及异常完整核对。描述变化丢弃帧并交由公共有界暂态处理；描述无法体现的前面板修改需要主动刷新。协议没有可靠采集序号，不把相同数据哈希当成重复触发，也不报告新触发率。

`auto_setup` 查询 `:AUToset:ENAble?`，禁用时拒绝，启用时只发送一次 `:AUToset`，沿用有界完成标记和错误查询；不改自动设置搜索策略。完成后完整刷新参数与范围，运行状态由公共控制事务恢复软件监测。新增 Auto 及局部控制缓存仅离线验证，实机待测。

## 连接与驱动

Windows 10/11 x64、PyVISA、已有 `rs-visa` 组件；通过用户配置的 VISA SOCKET 资源连接，使用仪器自报 Socket 端口，不自动切换 VXI-11。扫描及备份使用 `configure_acquisition=False`，不写传输或采集模式设置。显式连接备份传输参数后准备 WORD；检测到 ROLL 时按已授权的 MAIN 策略保存原设置，将过长时基降至 20 ms/格并设置 MAIN，逐项完成同步及读回。短时基不升高，Auto ROLL 偏好和运行/停止状态保持；失败记录已尝试命令及最后读回，不重复设置。

组件的官方来源、版本、材料哈希/签名、分发与安装状态见 [组件清单](../../../deployment/components.json) 和 [部署规范](../../development/desktop-deployment.md)。本型号不增加厂商 DLL、驱动或后台服务，不修改网络/DHCP/防火墙。沿用现有离线维护缓存；安装、重启、回滚与目标电脑验收的待补项由公共部署台账维护。

Socket 有界接收先读声明长度，再接收正文并核对 LF/CRLF；超限、截断、尾随异常分别保留长度证据。中断后关闭连接，须显式重连；不清空后重用、不重放写入。
