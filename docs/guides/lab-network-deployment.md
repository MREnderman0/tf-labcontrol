# 实验网络部署与换电脑

应用程序可迁移，实验网配置按电脑生成。不能把开发电脑的网卡 GUID、IP、MAC 保留名单、程序安装路径、防火墙规则或租约复制为新电脑的默认配置。仪器用完整型号与序列号核验身份，IP 只是当前连接地址。参见[实验网发现](../architecture/lan-discovery.md)。

## 安装与环境修复目标

最终安装维护组件携带 DHCP 等离线材料，用户首次选择实验网口后自动完成必要配置；设置内“环境与修复”复用同一执行器。当前只交付检查、方案和报告，执行器后续实现，详见[部署规范](../development/desktop-deployment.md)。

## 两种网络环境

- 网络已有 DHCP（例如实验路由器）：电脑和支持的仪器使用该 DHCP，软件发现并核验新地址，不另开服务器。
- 电脑与仪器只连接普通交换机：交换机不负责分配地址。可以采用明确配置的同网段静态地址、厂商支持的 AutoIP，或由电脑在指定实验有线网口提供 DHCP。

提供 DHCP 时使用通用动态地址池，任意接入该实验网的 DHCP 客户端都可申请；不按型号、序列号或 MAC 白名单准入。地址保留仅用于某些设备需要稳定地址的情况，不能替代通用地址池。Tftpd64 的 `PoolSize=0` 会忽略没有保留地址的请求，且不写常规请求日志；因此“日志没出现设备”不能单独证明线缆不通。依据：[厂商服务源码](https://github.com/PJO2/tftpd64/blob/master/src/_services/bootpd.c)。

## 当前可用的配置准备入口

以下命令只读取本机网络并生成部署方案，不启动 DHCP、不修改地址/防火墙、不扫描仪器或打开 VISA：

```powershell
lab-control-cli network inspect
lab-control-cli network plan --interface "本机实验网卡名称" --plan-file lab-network-plan.json
lab-control-cli network validate --plan-file lab-network-plan.json
```

源码环境可将 `lab-control-cli` 替换为 `.venv-dev\Scripts\python.exe -m lab_control.cli.main`。`inspect` 返回当前物理网卡、地址、默认路由和本机 UDP 67 监听者；没有监听者不等于网络上没有其他 DHCP 服务器。

`plan` 必须指定当前网卡名称或 ID。默认生成 100 个地址、24 小时租期的通用池；按本机现有私有 IPv4 网段计算，不固定任何现场网段。可用 `--server-address` 选择多地址网卡上的现有地址，`--pool-start`、`--pool-size`、`--lease-minutes` 调整范围，重复 `--exclude` 排除已知固定/保留地址。自动计算只避开本机及显式排除地址，尚未探测实际占用；不足时明确报错，不扩大网段。规划拒绝 Wi-Fi、断开的网口及正在通过 DHCP 获取地址的服务端地址。

方案包含本机指纹、当前网卡与网段、路由/DNS/网络类型恢复快照和执行顺序；有默认网关的实验口及与其他接口/VPN 路由冲突的网段会被拒绝。方案，保存在本机运行资料中，不随软件发行。`validate` 遇到另一台电脑、换网卡、地址/前缀变化或方案不一致会拒绝继续，需重新 `inspect` / `plan`。重复写已有方案文件也会拒绝，保留原文件。

## 启用与验证

1. 先确认选中的是实验网口、网络中没有另一台负责同网段分配的 DHCP 服务器，并检查候选池实际占用。排除电脑、网关、仪器固定地址及已有保留地址；启用分配前地址冲突检查。不要凭“没有 ARP 回应”宣称所有关机设备的固定地址均已排除。
2. 在这台电脑安装或定位经批准的 DHCP 运行库。依赖下载遵循[国内镜像与直连规范](../development/environment.md)，不携带开发机的绝对安装路径。
3. 根据方案配置通用池、掩码、租期和所选实验网口绑定；Windows 防火墙按本机可执行文件及网卡限定 DHCP 入站。隔离实验网不填写不存在的互联网网关或 DNS。已有设备的稳定地址保留在池外。
4. 保存服务器配置并核对实际生效值及重启后的值。让仪器重新应用 DHCP；检查 Discover / Offer / Request / ACK，并使用 PyVISA 只读核验完整型号和序列号。连接成功与物理输出验收分开记录。
5. 依据[实机留档规范](../testing/records.md)保存前后配置、哈希、请求/分配证据及身份响应。真实地址、MAC、序列号和报文只保存在运行目录。

目前准备与校验入口已提供；厂商 DHCP 的安装、启用及 Windows 权限步骤仍属于部署操作，未集成为 GUI 一键安装向导。普通启动和“扫描”不会自动启用 DHCP。自动发现支持换电脑，不代表已完成 DHCP 服务自动迁移或实际跨电脑验收。

## 换电脑实测踩坑与安装器门禁

2026-10-02 在一台 Windows 电脑上完成了 Tftpd64 服务部署回读。服务自动启动、UDP 67 监听、仅以太网防火墙规则、DHCP-only 配置和本机 Discover/Offer 自测均通过；真实设备没有租约，VISA LAN 仍为 0。完整原始证据只保存在运行目录的 `hardware-tests/dhcp-<批次>/`，不能把本机自测写成设备验收。

后续安装器或“环境与修复”执行器必须把这些条件作为逐项门禁：

| 换电脑风险 | 自动处理要求 |
| --- | --- |
| 本次用户未看到管理员提示；远程/托管环境可能影响提示可见性，具体原因未确认 | 提供明确可见的管理员维护入口；提权失败或被取消要显示，等待须可取消且有超时，不自动重试 |
| `%LOCALAPPDATA%` 可能被打包/商店环境重定向（本次 Codex 打包环境实际出现数据库/锁文件重定向） | 核对运行目录物理路径；重定向时拒绝真实硬件 I/O，改用用户确认的物理 `LAB_CONTROL_HOME` 后重新检查；不复制旧电脑绝对路径 |
| 网卡名称、InterfaceIndex、GUID、MAC 会变化 | 重新枚举已连接物理 Ethernet，让用户确认；不复用旧网卡绑定 |
| 实验口有默认网关、VPN 重叠网段或已有 DHCP 监听者 | 阻止执行并保留前态；不能影响 WLAN 默认路由 |
| 普通交换机不提供 DHCP | 使用通用池，验证 Discover/Offer/Request/ACK；服务自测和真实设备 ACK 分开显示 |
| 系统 DHCP-In 规则只覆盖客户端端口 68 | 按当前服务路径和选定网卡创建 UDP 67、远端 68 规则，保存并读回前后规则 |
| Tftpd64 默认可能启用多项服务或 `PoolSize=0` | 只启用 DHCP (`Services=4`)，池大小大于 0，Gateway/DNS 为空，并读回实际配置 |
| 设备可能不会立即续租 | 安装完成后提示重新应用 DHCP；需要重新上电/重插网线时先结束采集并保存设备状态，等待租约变化后再扫描 |
| DHCP 正常但设备不广播 VXI-11/mDNS | 不做子网/端口扫描；要求明确地址后只读身份核验，不能把 DHCP 通过当作 LAN 发现通过 |
| 失败时可能破坏用户网络 | 维护进程持有硬件锁，保存地址、DHCP、DNS、路由、服务、防火墙快照；只回滚本应用拥有且未被外部修改的内容，不自动重启 |

组件只有在干净 Windows 10/11 电脑完成离线安装、管理员维护、重启后服务恢复和真实设备 ACK 后才可从 `pending` 变为 `verified`。当前仓库只提供检查/方案入口；本批次的管理员脚本是开发机验证材料，不是可跨电脑复用的网络绑定配置。

## 迁移边界

可以迁移需要保留的资产名称、槽位、实验限值及历史记录；连接地址重新发现后核验。新电脑重新安装相应 VISA/厂商运行库，选择实验网口并生成本机配置。不要迁移旧租约、旧网卡绑定、另一台电脑的计划任务或防火墙规则；旧部署方案仅作为审计记录。
